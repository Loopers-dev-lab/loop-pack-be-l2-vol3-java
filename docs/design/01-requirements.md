# Requirements

# 공통

## 범위 제외 사항

| 항목 | 사유 |
| --- | --- |
| 회원 (User) | 회원가입, 내 정보 조회, 비밀번호 변경은 이미 구현 완료 |
| 결제 (Payment) | 추후 별도 개발 예정 |
| 주문 상태 관리 | 결제 플로우 확정 후 설계 예정 |

## 유비쿼터스 언어

| 한글 | 영문 | 정의 |
| --- | --- | --- |
| 브랜드 | Brand | 상품을 그룹화하는 입점 브랜드 |
| 상품 | Product | 고객이 탐색하고 주문하는 판매 단위 |
| 재고 수량 | Stock Quantity | 판매 가능한 상품 수량 |
| 좋아요 | Like | 사용자가 상품에 표시하는 관심 표현 |
| 주문 | Order | 사용자의 상품 구매 요청 |
| 주문 상품 | Order Item | 주문에 포함된 개별 상품 항목 |
| 스냅샷 | Snapshot | 주문 시점의 상품 정보 복사본 |

## 공통 용어정리

- **활성**: 삭제되지 않은 정상 운영 상태를 의미한다
- **삭제**: 서비스 노출 차단을 의미하며, 운영 기록 보관을 위해 실제 데이터는 파기하지 않는다
- **미존재**: 
    - 데이터가 존재하지 않거나 삭제 상태이거나, 요청자에게 접근 권한이 없는 경우를 의미한다
    - 타인의 리소스 접근 시에도 리소스 존재 여부를 노출하지 않기 위해 동일하게 미존재로 응답한다.
- **데이터 없음**: 해당 ID의 데이터가 DB에 존재하지 않는 경우를 의미한다

## 접근 권한 정의

| 구분 | 인증 방식 | 설명 |
| --- | --- | --- |
| Admin | X-Loopers-Ldap 헤더 | LDAP 인증된 **관리자**만 접근 가능 |
| User (인증 필요) | X-Loopers-LoginId + LoginPw 헤더 | **로그인된 사용자**만 접근 가능 |
| User (인증 불필요) | 없음 | **비로그인 사용자**도 접근 가능 |

# 브랜드(Brand) & 상품(Product)

## User Scenario

- **사용자**: 브랜드 정보를 확인하고, 해당 브랜드에 속한 최신/인기 **상품을 탐색**하여 **구매 결정**을 내릴 수 있다
- **관리자**: 입점 **브랜드의 정보를 관리**하고, 상품을 등록/수정/삭제하여 서비스의 데이터를 최신으로 유지한다

## Feature List

### 브랜드

| ID | 기능 명칭 | 대상 | 인증 | API | 설명 |
| --- | --- | --- | --- | --- | --- |
| BR-01 | 브랜드 등록 | Admin | LDAP | POST /api-admin/v1/brands | 새로운 입점 브랜드 정보 생성 |
| BR-02 | 브랜드 정보 수정 | Admin | LDAP | PATCH /api-admin/v1/brands/{brandId} | 브랜드 정보 변경 |
| BR-03 | 브랜드 삭제 | Admin | LDAP | DELETE /api-admin/v1/brands/{brandId} | 브랜드 운영 종료 및 하위 상품 노출 차단 |
| BR-04 | 브랜드 목록 조회 | Admin | LDAP | GET /api-admin/v1/brands | 관리용 전체 브랜드 리스트 (페이징) |
| BR-05 | 브랜드 상세 조회 | Admin | LDAP | GET /api-admin/v1/brands/{brandId} | 관리용 브랜드 상세 정보 확인 |
| BR-06 | 브랜드 목록 조회 | User | 불필요 | GET /api/v1/brands | 고객용 활성 브랜드 리스트 |
| BR-07 | 브랜드 정보 조회 | User | 불필요 | GET /api/v1/brands/{brandId} | 고객용 브랜드 프로필 정보 |

## Business Rule

### 공통 (브랜드 & 상품)

| 규칙 | 설명 |
| --- | --- |
| 삭제 데이터 관리 | 어드민은 삭제된 브랜드, 상품도 조회할 수 있다 |
| 삭제 데이터 노출 차단 | 사용자에게는 활성 브랜드, 상품만 노출한다 |

### 브랜드

| 규칙 | 설명 |
| --- | --- |
| 브랜드명 유일성 | 브랜드명은 삭제 여부와 관계없이 중복할 수 없다 |
| 브랜드 삭제 연쇄 | 브랜드 삭제 시 해당 브랜드에 속한 모든 상품도 삭제 상태로 변경한다 |

### 상품

| 규칙 | 설명 |
| --- | --- |
| 브랜드 필수 소속 | 상품은 반드시 활성 상태의 브랜드에 소속되어야 한다 |
| 브랜드 변경 불가 | 상품 등록 후 소속 브랜드는 변경할 수 없다 |

## Use Case Flow

### [BR-01] 브랜드 등록

- **Main Flow**
    1. 관리자가 등록할 브랜드 정보를 입력하고 등록을 요청한다
    2. 브랜드명의 중복 여부를 확인한다
    3. 새로운 브랜드를 활성 상태로 저장한다
- **Exception Flow**
    - **[브랜드명 중복 발생]**: 이미 존재하는 브랜드명일 경우 등록을 거부하고 “이미 등록된 브랜드입니다” 안내를 노출한다

### [BR-02] 브랜드 정보 수정

- **Main Flow**
    1. 관리자가 수정할 브랜드를 선택하고 정보 수정을 요청한다
    2. 해당 브랜드의 존재 여부를 확인한다
    3. 브랜드명 변경 시, 다른 브랜드와의 중복 여부를 확인한다
    4. 브랜드 정보를 수정한다
- **Exception Flow**
    - **[브랜드 미존재]**: 브랜드가 미존재할 경우 수정을 거부하고 “존재하지 않는 브랜드입니다” 안내를 노출한다
    - **[브랜드명 중복 발생]**: 이미 존재하는 브랜드명일 경우 수정을 거부하고 “이미 등록된 브랜드입니다” 안내를 노출한다

### [BR-03] 브랜드 삭제

- **Main Flow**
    1. 관리자가 삭제할 브랜드를 선택하고 삭제를 요청한다
    2. 해당 브랜드의 존재 여부를 확인한다
    3. 해당 브랜드를 삭제 상태로 변경한다
    4. 해당 브랜드에 속한 모든 상품도 삭제 상태로 변경한다
- **Exception Flow**
    - **[브랜드 미존재]**: 브랜드가 미존재할 경우 삭제를 거부하고 “존재하지 않는 브랜드입니다” 안내를 노출한다

### [BR-04] 브랜드 목록 조회 (Admin)

- **Main Flow**
    1. 관리자가 브랜드 목록 조회를 요청한다
    2. 전체 브랜드를 최신 등록순으로 페이징하여 반환한다
- **Alternate Flow**
    - **[브랜드명 검색]**: 브랜드명 키워드로 검색하여 반환한다
    - **[상태 필터]**: 활성/삭제 상태별로 필터링하여 반환한다

### [BR-05] 브랜드 상세 조회 (Admin)

- **Main Flow**
    1. 관리자가 조회할 브랜드를 선택하여 상세 정보 조회를 요청한다
    2. 해당 브랜드의 데이터 존재 여부를 확인한다
    3. 해당 브랜드의 기본 정보와 관리용 데이터를 반환한다
- **Alternate Flow**
    - **[삭제된 브랜드]**: 삭제 상태의 브랜드도 조회 가능하며, 삭제 상태임을 표시하여 반환한다
- **Exception Flow**
    - **[브랜드 데이터 없음]**: 해당 ID의 브랜드 데이터가 존재하지 않을 경우 조회를 거부하고 “존재하지 않는 브랜드입니다” 안내를 노출한다

### [BR-06] 브랜드 목록 조회 (User)

- **Main Flow**
    1. 사용자가 브랜드 목록 조회를 요청한다
    2. 활성 브랜드만 이름 오름차순으로 페이징하여 반환한다
- **Alternate Flow**
    - [브랜드명 검색]: 브랜드명 키워드로 검색하여 반환한다

### [BR-07] 브랜드 정보 조회 (User)

- **Main Flow**
    1. 사용자가 조회할 브랜드를 선택하고 브랜드 정보 조회를 요청한다
    2. 해당 브랜드의 존재 여부를 확인한다
    3. 해당 브랜드의 기본 정보를 반환한다
- **Exception Flow**
    - [브랜드 미존재]: 브랜드가 미존재할 경우 조회를 거부하고 “존재하지 않는 브랜드입니다” 안내를 노출한다

### [PR-01] 상품 등록

- **Precondition**
    - 해당 브랜드가 존재해야 한다
- **Main Flow**
    1. 관리자가 등록할 상품 정보를 입력하고 등록을 요청한다
    2. 상품을 활성 상태로 등록한다
- **Exception Flow**
    - **[브랜드 미존재]**: 소속 브랜드가 미존재할 경우 등록을 거부하고 “존재하지 않는 브랜드입니다” 안내를 노출한다

### [PR-02] 상품 정보 수정

- **Main Flow**
    1. 관리자가 수정할 상품을 선택하고 정보 수정을 요청한다
    2. 해당 상품의 존재 여부를 확인한다
    3. 상품 정보를 수정한다 (소속 브랜드는 변경할 수 없다)
- **Exception Flow**
    - **[상품 미존재]**: 상품이 미존재할 경우 수정을 거부하고 “존재하지 않는 상품입니다” 안내를 노출한다

### **[PR-03] 상품 삭제**

- **Main Flow**
    1. 관리자가 삭제할 상품을 선택하고 삭제를 요청한다
    2. 해당 상품의 존재 여부를 확인한다
    3. 해당 상품을 삭제 상태로 변경한다
- **Exception Flow**
    - **[상품 미존재]**: 상품이 미존재할 경우 삭제를 거부하고 “존재하지 않는 상품입니다” 안내를 노출한다

### [PR-04] 상품 목록 조회 (Admin)

- **Main Flow**
    1. 관리자가 상품 목록 조회를 요청한다
    2. 전체 상품을 최신 등록순으로 페이징하여 반환한다
- **Alternate Flow**
    - **[상품명 검색]**: 상품명 키워드로 검색하여 반환한다
    - **[브랜드 필터]**: 특정 브랜드를 선택하여 해당 브랜드에 속한 상품만 필터링하여 반환한다
    - **[상태 필터]**: 활성/삭제 상태별로 필터링하여 반환한다

### [PR-05] 상품 상세 조회 (Admin)

- **Main Flow**
    1. 관리자가 조회할 상품을 선택하고 상세 정보 조회를 요청한다
    2. 해당 상품의 데이터 존재 여부를 확인한다
    3. 해당 상품의 기본 정보와 관리용 데이터를 반환한다
- **Alternate Flow**
    - **[삭제된 상품]**: 삭제 상태의 상품도 조회 가능하며, 삭제 상태임을 표시하여 반환한다
- **Exception Flow**
    - **[상품 데이터 없음]**: 해당 ID의 상품 데이터가 존재하지 않을 경우 조회를 거부하고 “존재하지 않는 상품입니다” 안내를 노출한다

### [PR-06] 상품 목록 조회 (User)

- **Main Flow**
    1. 사용자가 상품 목록 조회를 요청한다
    2. 활성 상품만 조회하여 최신순으로 페이징하여 반환한다
- **Alternate Flow**
    - **[브랜드 필터]**: 특정 브랜드를 선택하여 해당 브랜드에 속한 상품만 필터링하여 반환한다
    - **[정렬]**: 최신순, 가격 오름차순, 좋아요 내림차순 정렬 기준을 변경하여 반환한다

### [PR-07] 상품 상세 조회 (User)

- **Main Flow**
    1. 사용자가 조회할 상품을 선택하고 상세 정보 조회를 요청한다
    2. 해당 상품의 존재 여부를 확인한다
    3. 상품 상세 정보를 반환한다
- **Exception Flow**
    - **[상품 미존재]**: 상품이 미존재할 경우 조회를 거부하고 “존재하지 않는 상품입니다” 안내를 노출한다

# 좋아요

## User Scenario

- 사용자: 관심 있는 상품에 좋아요를 등록하여 나중에 모아볼 수 있다

## Feature List

| ID | 기능 명칭 | 대상 | 인증 | API | 설명 |
| --- | --- | --- | --- | --- | --- |
| LK-01 | 상품 좋아요 등록 | User | 필요 | POST /api/v1/products/{productId}/likes | 상품에 좋아요 추가 |
| LK-02 | 상품 좋아요 취소 | User | 필요 | DELETE /api/v1/products/{productId}/likes | 상품에 좋아요 해제 |
| LK-03 | 좋아요 상품 목록 조회 | User | 필요 | GET /api/v1/likes | 사용자가 좋아요한 상품 리스트 |

## Business Rule

| 규칙 | 설명 |
| --- | --- |
| 1인 1좋아요 | 한 사용자는 하나의 상품에 한 번만 좋아요할 수 있다 |
| 좋아요 멱등성 | 이미 좋아요한 상품에 재요청 시 현재 상태를 유지한다 |
| 취소 멱등성 | 좋아요가 없는 상품에 취소 요청 시 현재 상태를 유지한다 |
| 물리적 삭제 | 좋아요 취소 시 데이터를 물리적으로 삭제한다 |
| 삭제 상품 좋아요 불가 | 미존재 상품에는 좋아요를 등록할 수 없다 |
| 삭제 상품 취소 허용 | 상품이 삭제되어도 좋아요 취소는 가능하다 |

## Use Case Flow

### [LK-01] 상품 좋아요 등록

- **Precondition**
    - 대상 상품이 존재해야 한다
- **Main Flow**
    1. 사용자가 좋아요 등록을 요청한다
    2. 해당 상품의 좋아요 존재 여부를 확인한다
    3. 해당 상품에 좋아요를 등록한다
- **Alternate Flow**
    - **[이미 좋아요 상태]**: 이미 좋아요한 상품일 경우 현재 상태를 유지한다
- **Exception Flow**
    - **[상품 미존재]**: 상품이 미존재할 경우 등록을 거부하고 “존재하지 않는 상품입니다” 안내를 노출한다

### [LK-02] 상품 좋아요 취소

- **Main Flow**
    1. 사용자가 좋아요 취소를 요청한다
    2. 해당 상품의 좋아요 존재 여부를 확인한다
    3. 해당 상품의 좋아요를 물리적으로 삭제한다
- **Alternate Flow**
    - **[이미 취소 상태]**: 좋아요가 없는 상품일 경우 현재 상태를 유지한다

### [LK-03] 좋아요 상품 목록 조회

- **Main Flow**
    1. 사용자가 좋아요한 상품 목록 조회를 요청한다
    2. 사용자가 좋아요한 활성 상품만 최신순으로 페이징하여 반환한다

# 주문

## User Scenario

- 사용자: 여러 상품을 한 번에 주문하고, 주문 내역을 조회하여 구매 이력을 확인할 수 있다
- 관리자: 전체 주문 내역을 조회하여 주문 현황을 관리한다

## Feature List

| ID | 기능 명칭 | 대상 | 인증 | API | 설명 |
| --- | --- | --- | --- | --- | --- |
| OD-01 | 주문 요청 | User | 필요 | POST /api/v1/orders | 상품 재고 확인 및 차감 후 주문 생성 |
| OD-02 | 주문 목록 조회 | User | 필요 | GET /api/v1/orders | 기간별 주문 내역 조회 |
| OD-03 | 주문 상세 조회 | User | 필요 | GET /api/v1/orders/{orderId} | 단일 주문 상세 정보 확인 |
| OD-04 | 주문 목록 조회 | Admin | LDAP | GET /api-admin/v1/orders | 관리용 전체 주문 리스트 (페이징) |
| OD-05 | 주문 상세 조회 | Admin | LDAP | GET /api-admin/v1/orders/{orderId} | 관리용 단일 주문 상세 정보 확인 |

## Business Rule

| 규칙 | 설명 |
| --- | --- |
| 재고 충분성 | 주문 상품의 재고가 주문 수량 이상이어야 한다 |
| 전체 실패 | 주문 상품 중 하나라도 재고가 부족하면 전체 주문이 실패한다 |
| 재고 즉시 차감 | 주문 성공 시 재고를 즉시 차감한다 |
| 스냅샷 보존 | 주문 시점의 상품 정보(상품명, 가격, 브랜드명)를 스냅샷으로 저장한다 |
| 스냅샷 불변 | 원본 브랜드/상품이 수정/삭제되어도 주문 스냅샷은 영향받지 않는다 |
| 주문 데이터 보존 | 주문 데이터는 삭제할 수 없다 |
| 본인 주문만 조회 | 사용자는 본인의 주문만 조회할 수 있으며, 타인의 주문 접근 시 미존재로 응답한다 |

## Use Case Flow

### [OD-01] 주문 요청

- **Precondition**
    - 주문 상품이 모두 존재해야 한다
    - 주문 상품의 재고가 충분해야 한다
- **Main Flow**
    1. 사용자가 주문할 상품 목록과 수량을 입력하고 주문을 요청한다
    2. 주문 상품의 재고를 차감한다
    3. 주문 시점의 상품 정보를 스냅샷으로 저장한다
    4. 주문을 생성한다
- **Exception Flow**
    - **[상품 미존재]**: 주문 상품 중 미존재 상품이 포함된 경우 주문을 거부하고 "존재하지 않는 상품이 포함되어 있습니다" 안내를 노출한다
    - **[재고 부족]**: 주문 상품의 재고가 부족할 경우 주문을 거부하고 "재고가 부족한 상품이 있습니다" 안내를 노출한다

### [OD-02] 주문 목록 조회 (User)

- **Main Flow**
    1. 사용자가 조회 기간을 지정하고 주문 목록 조회를 요청한다
    2. 사용자의 주문만 최신순으로 페이징하여 반환한다
- **Alternate Flow**
    - **[기간 필터]**: 시작일, 종료일을 지정하여 해당 기간 내 주문만 필터링하여 반환한다 (각각 선택 적용 가능)

### [OD-03] 주문 상세 조회 (User)

- **Main Flow**
    1. 사용자가 조회할 주문을 선택하고 상세 정보 조회를 요청한다
    2. 해당 주문의 존재 여부를 확인한다
    3. 주문 정보와 스냅샷 상품 정보를 반환한다
- **Exception Flow**
    - **[주문 미존재]**: 해당 ID의 주문 데이터가 존재하지 않거나 본인의 주문이 아닐 경우 조회를 거부하고 "존재하지 않는 주문입니다" 안내를 노출한다

### [OD-04] 주문 목록 조회 (Admin)

- **Main Flow**
    1. 관리자가 주문 목록 조회를 요청한다
    2. 전체 주문을 최신순으로 페이징하여 반환한다

### [OD-05] 주문 상세 조회 (Admin)

- **Main Flow**
    1. 관리자가 조회할 주문을 선택하고 상세 정보 조회를 요청한다
    2. 해당 주문의 데이터 존재 여부를 확인한다
    3. 주문 정보와 스냅샷 상품 정보를 반환한다
- **Exception Flow**
    - **[주문 데이터 없음]**: 해당 ID의 주문 데이터가 존재하지 않을 경우 조회를 거부하고 "존재하지 않는 주문입니다" 안내를 노출한다
