# Thundering Herd

## 핵심 개념

대기열에서 N명에게 토큰을 한꺼번에 발급하면, **N명이 동시에 주문 API를 호출**합니다.
이 순간 트래픽이 폭발적으로 증가하는 현상 = **Thundering Herd**.

## 발생 시나리오

```
스케줄러가 100명에게 동시 토큰 발급
→ 100명이 동시에 주문 API 호출
→ DB 커넥션 100개 동시 요청
→ 커넥션 풀 고갈 → 장애
```

결국 대기열을 만들어 놓고, 입장 시점에 또 폭발이 발생하는 상황.

## 대응 방법

### 1. 배치 크기 제한
```
N = 커넥션 수 × (주기 / 평균 처리 시간)
→ 커넥션 풀이 감당 가능한 수준으로만 발급
```

### 2. 순차 발급 (Staggered Release)
```
100명을 한 번에 발급하지 않고
10명씩 1초 간격으로 발급
→ 트래픽을 시간에 분산
```

### 3. 토큰 TTL로 자연 분산
토큰 받은 즉시 주문하는 사람과 잠시 후 주문하는 사람이 자연스럽게 분산됨.

## 퀴즈 Q&A

**Q. 스케줄러가 매 5초마다 50명에게 토큰을 발급한다. Thundering Herd가 발생하는 이유와 해결책은?**
A. 50명이 동시에 API를 호출하면 DB 커넥션을 50개 동시 점유. 배치 크기를 커넥션 풀 기준으로 제한하거나 순차 발급으로 분산해야 함.
