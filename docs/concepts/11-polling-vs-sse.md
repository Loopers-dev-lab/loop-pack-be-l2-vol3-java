# Polling vs SSE

## 핵심 개념

순번을 실시간으로 사용자에게 보여주는 방법 두 가지.

## 비교

| | Polling | SSE (Server-Sent Events) |
|-|---------|--------------------------|
| 방식 | 클라이언트가 주기적으로 서버에 요청 | 서버가 클라이언트에 이벤트 푸시 |
| 연결 | 요청마다 짧게 연결 후 끊음 | 연결을 계속 유지 (단방향) |
| 서버 부하 | 요청 수 많음 (주기 × 사용자 수) | 연결 수 많음 (동시 접속자 수 = 연결 수) |
| 구현 복잡도 | 단순 | 복잡 (연결 관리, 재연결 처리) |
| 실무 선택 | ✅ 안정적 | 대규모 동시 접속 시 연결 유지 비용 |

## Polling 방식

```
클라이언트: 3초마다 GET /queue/position 호출
서버: 현재 순번 반환
```

연결이 짧고 단순. 주기를 조정해서 부하 제어 가능.

## SSE 방식

```
클라이언트: GET /queue/stream 요청 (연결 유지)
서버: 순번 바뀔 때마다 이벤트 전송
```

10만 명이 대기 중이면 서버가 10만 개의 연결을 유지해야 함.

## 실무에서 Polling을 선택하는 이유

- 연결 유지보다 짧은 요청이 서버 자원 관리에 유리
- 서버 재시작/배포 시 SSE 연결 전부 끊김 → 재연결 로직 필요
- Polling 주기를 조절해서 부하 쉽게 제어 가능

## 퀴즈 Q&A

**Q. 10만 명이 대기 중일 때 SSE의 문제는?**
A. 서버가 10만 개의 연결을 동시에 유지해야 함. 메모리와 파일 디스크립터 소모가 큼. Polling은 연결이 짧으므로 이 문제가 없음.
