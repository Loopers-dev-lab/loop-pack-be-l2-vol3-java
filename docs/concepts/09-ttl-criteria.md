# TTL 기준 산정

## 핵심 개념

TTL = **사용자가 주문을 완료하기까지 걸리는 최대 시간**

```
TTL = 상품 확인 + 수량 선택 + 결제 정보 입력 + 결제 완료
```

## 산정 방법

| 상황 | 방법 |
|------|------|
| 기존 서비스 | 실제 데이터에서 P95 주문 완료 시간 측정 |
| 신규 서비스 | UX 흐름 예상 시간 + 여유 20~30% |

**예**: P95 주문 완료 시간이 4분 → TTL = **5~6분**

## 트레이드오프

| TTL | 문제 |
|-----|------|
| 너무 짧게 (1분) | 결제 중 토큰 만료 → 사용자가 처음부터 다시 대기해야 함 |
| 너무 길게 (30분) | 토큰 받고 자리만 점유하는 유저 증가 → 실제 대기자 손해 |

## 퀴즈 Q&A

**Q. TTL을 5분으로 설정했는데 사용자가 4분 58초에 주문 완료했다. 적절한 TTL인가? TTL이 3분이었다면?**
A. 5분 TTL은 허용 범위 내로 통과. 3분 TTL이었다면 4분 58초 시점에 이미 토큰 만료 → 주문 실패 → 대기열 처음부터 다시 시작해야 함.
