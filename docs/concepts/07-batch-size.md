# 배치 크기 N 산정

## 핵심 공식

```
N = 커넥션 수 × (스케줄 주기 / 평균 처리 시간)
```

## 공식 유도

스케줄러가 N명에게 토큰을 발급하면, N명이 동시에 주문 API를 호출합니다.
각 요청은 DB 커넥션을 평균 처리 시간 동안 점유합니다.

```
커넥션 10개, 평균 처리 시간 1초, 스케줄 주기 5초라면?

5초 동안 커넥션 10개가 처리할 수 있는 요청 수
= 10개 × (5초 / 1초)
= 50명
```

→ N = 50을 초과하면 커넥션이 부족해져 대기 타임아웃 발생.

## 실전 예시

| 조건 | 계산 |
|------|------|
| HikariCP 기본값 10, 처리 500ms, 주기 5초 | 10 × (5 / 0.5) = **100명** |
| HikariCP 10, 처리 2초, 주기 10초 | 10 × (10 / 2) = **50명** |

## 주의사항

- 평균 처리 시간은 실측값 기반으로 (P95 권장)
- 여유 버퍼를 위해 계산값의 80% 수준으로 설정 권장
- 처리 시간이 가변적이면 N을 보수적으로 잡을 것

## 퀴즈 Q&A

**Q. HikariCP pool-size=10, 평균 처리 시간=1초, 스케줄 주기=10초일 때 최대 N은?**
A. 10 × (10 / 1) = 100명. 실전에서는 80명 수준으로 여유 두는 것을 권장.
