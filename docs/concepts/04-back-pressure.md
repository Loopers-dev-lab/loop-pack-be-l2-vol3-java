# Back-pressure — 대기열의 본질

## 핵심 개념

**Back-pressure**: 시스템이 처리 가능한 속도를 초과하는 요청을 **의도적으로 지연/제한**하는 것.

```
처리 가능량: 초당 10건
들어오는 요청: 초당 100건

→ 90건을 어떻게 처리할 것인가?
  - 거절(Rate Limiting): "지금 안 돼요, 나중에 다시 시도하세요"
  - 대기(Back-pressure): "번호표 드릴게요, 기다리세요"
```

## 대기열이 Back-pressure를 구현하는 방법

```
사용자 → Redis 대기열 등록 (즉시 번호 발급)
       ↓
스케줄러가 주기적으로 N명씩 토큰 발급
       ↓
토큰 보유자만 주문 API 접근 가능
       ↓
처리 완료 → 토큰 제거 → 다음 N명 진입
```

시스템이 처리 가능한 속도(N명/주기)만큼만 진입시킵니다.

## 흔한 실수

| 실수 | 결과 |
|------|------|
| 대기열 없이 바로 DB 접근 | 트래픽 급증 시 즉시 장애 |
| Polling 주기 너무 짧게 | 순번 조회 요청 자체가 부하 |
| 토큰 TTL 미설정 | 유령 사용자 자리 점유 |
| 순번 계산을 DB에서 수행 | 성능 저하 |

## 퀴즈 Q&A

**Q. Back-pressure가 없으면 트래픽 급증 시 어떤 일이 벌어지는가?**
A. DB 커넥션 풀 고갈 → Connection not available 에러 → 응답 시간 급증 → 서버 다운.
