# 재고 점유 및 확정

## 배경
주문 생성 시 재고를 즉시 차감하면 결제 실패 시 재고가 차감된 채로 남는 문제가 있다. 재고를 점유(reserve) → 확정(confirm) 모델로 전환하여, 결제 성공 시에만 최종 차감을 확정한다.

## API
내부 호출 (외부 API 없음)

## 인증
불필요 (시스템 내부 호출)

## 인수 조건

### 재고 점유 (ST-01)
- [ ] 주문 생성 시 주문 상품의 가용 재고(총 재고 - 점유 수량 - 확정 차감 수량)가 주문 수량 이상이면 점유에 성공한다
- [ ] 점유 성공 시 해당 상품의 점유 수량이 주문 수량만큼 증가한다
- [ ] 점유 성공 시 가용 재고가 주문 수량만큼 감소한다
- [ ] 점유 성공 시 총 재고(quantity)는 변하지 않는다
- [ ] 주문 상품 중 하나라도 가용 재고가 부족하면 전체 점유가 실패한다
- [ ] 전체 점유 실패 시 어떤 상품의 점유 수량도 증가하지 않는다
- [ ] 동시에 같은 상품에 점유 요청이 들어와도 가용 재고를 초과하여 점유되지 않는다
- [ ] 해당 상품의 재고 정보가 존재하지 않으면 400 응답, 메시지: "재고 정보가 존재하지 않습니다"
- [ ] 가용 재고가 부족하면 400 응답, 메시지: "재고가 부족한 상품이 있습니다"

### 재고 확정 (ST-02)
- [ ] 결제 성공 시 점유된 재고의 점유 수량이 주문 수량만큼 감소한다
- [ ] 결제 성공 시 확정 차감 수량이 주문 수량만큼 증가한다
- [ ] 확정 후 가용 재고는 변하지 않는다 (점유 수량 감소와 확정 차감 수량 증가가 상쇄)
- [ ] 확정 후 총 재고(quantity)는 변하지 않는다

## 제약
- Stock은 Product와 별도 엔티티로 분리되며, productId로 연결한다
- 재고 점유와 주문 생성은 같은 트랜잭션에서 처리한다
- 재고 확정과 주문 PAID 전이는 같은 트랜잭션에서 처리한다
- 기존 Product.stockQuantity 필드는 Stock 도메인으로 이관한다
