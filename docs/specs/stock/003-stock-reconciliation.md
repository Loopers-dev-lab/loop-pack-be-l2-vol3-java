# 재고 보정

## 배경
인프로세스 보상 트랜잭션이 실패하거나 시스템 장애로 상태 불일치가 발생할 수 있다. 스케줄러가 주기적으로 불일치를 탐지하고 보정하여 재고 정합성을 보장한다.

## API
스케줄러 (외부 API 없음)

## 인증
불필요 (시스템 내부 실행)

## 인수 조건

### 점유 누수 보정
- [ ] 주문 상태가 CANCELED인데 점유가 남아있는 건을 탐지한다
- [ ] 탐지된 건의 점유를 해제하여 가용 재고를 복원한다
- [ ] 보정 처리된 건수를 로그로 기록한다

### 확정 누락 보정
- [ ] 결제 상태가 SUCCEEDED인데 재고가 미확정(점유 상태)인 건을 탐지한다
- [ ] 탐지된 건의 재고를 확정 처리한다
- [ ] 보정 처리된 건수를 로그로 기록한다

### 스케줄러 실행
- [ ] 스케줄러는 설정 가능한 주기(N분)마다 실행된다
- [ ] 보정 대상이 없으면 아무 작업 없이 종료한다
- [ ] 보정 중 오류가 발생해도 다른 건의 보정은 계속 진행한다

## 제약
- 보정 스케줄러는 commerce-batch 모듈에서 실행한다
- 보정 주기는 application.yml에서 설정 가능하다
- 각 보정 건은 개별 트랜잭션으로 처리한다 (하나의 실패가 다른 건에 영향 주지 않음)
