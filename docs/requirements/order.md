# 주문

## User Scenario

- 사용자: 여러 상품을 한 번에 주문하고, 주문 내역을 조회하여 구매 이력을 확인할 수 있다
- 관리자: 전체 주문 내역을 조회하여 주문 현황을 관리한다

## Feature List

| ID | 기능 명칭 | 대상 | 인증 | API | 설명 |
| --- | --- | --- | --- | --- | --- |
| OD-01 | 주문 요청 | User | 필요 | POST /api/v1/orders | 상품 재고 확인 및 차감 후 주문 생성 |
| OD-02 | 주문 목록 조회 | User | 필요 | GET /api/v1/orders | 기간별 주문 내역 조회 |

## Business Rule

| 규칙 | 설명 |
| --- | --- |
| 재고 충분성 | 주문 상품의 재고가 주문 수량 이상이어야 한다 |
| 전체 실패 | 주문 상품 중 하나라도 재고가 부족하면 전체 주문이 실패한다 |
| 재고 즉시 차감 | 주문 성공 시 재고를 즉시 차감한다 |
| 스냅샷 보존 | 주문 시점의 상품 정보(상품명, 가격)를 스냅샷으로 저장한다 |
| 스냅샷 불변 | 원본 브랜드/상품이 수정/삭제되어도 주문 스냅샷은 영향받지 않는다 |
| 주문 데이터 보존 | 주문 데이터는 삭제할 수 없다 |
| 본인 주문만 조회 | 사용자는 본인의 주문만 조회할 수 있으며, 타인의 주문 접근 시 미존재로 응답한다 |

## Use Case Flow

### [OD-01] 주문 요청

- **Precondition**
    - 주문 상품이 모두 존재해야 한다
    - 주문 상품의 재고가 충분해야 한다
- **Main Flow**
    1. 사용자가 주문할 상품 목록과 수량을 입력하고 주문을 요청한다
    2. 주문 상품의 재고를 차감한다
    3. 주문 시점의 상품 정보를 스냅샷으로 저장한다
    4. 주문을 생성한다
- **Exception Flow**
    - **[상품 미존재]**: 주문 상품 중 미존재 상품이 포함된 경우 주문을 거부하고 "존재하지 않는 상품이 포함되어 있습니다" 안내를 노출한다
    - **[재고 부족]**: 주문 상품의 재고가 부족할 경우 주문을 거부하고 "재고가 부족한 상품이 있습니다" 안내를 노출한다

### [OD-02] 주문 목록 조회 (User)

- **Main Flow**
    1. 사용자가 조회 기간을 지정하고 주문 목록 조회를 요청한다
    2. 사용자의 주문만 최신순으로 페이징하여 반환한다
- **Alternate Flow**
    - **[기간 필터]**: 시작일, 종료일을 지정하여 해당 기간 내 주문만 필터링하여 반환한다 (각각 선택 적용 가능)

### [OD-03] 주문 상세 조회 (User)

- **Main Flow**
    1. 사용자가 조회할 주문을 선택하고 상세 정보 조회를 요청한다
    2. 해당 주문의 존재 여부를 확인한다
    3. 주문 정보와 스냅샷 상품 정보를 반환한다
- **Exception Flow**
    - **[주문 미존재]**: 해당 ID의 주문 데이터가 존재하지 않거나 본인의 주문이 아닐 경우 조회를 거부하고 "존재하지 않는 주문입니다" 안내를 노출한다

### [OD-04] 주문 목록 조회 (Admin)

- **Main Flow**
    1. 관리자가 주문 목록 조회를 요청한다
    2. 전체 주문을 최신순으로 페이징하여 반환한다

### [OD-05] 주문 상세 조회 (Admin)

- **Main Flow**
    1. 관리자가 조회할 주문을 선택하고 상세 정보 조회를 요청한다
    2. 해당 주문의 데이터 존재 여부를 확인한다
    3. 주문 정보와 스냅샷 상품 정보를 반환한다
- **Exception Flow**
    - **[주문 데이터 없음]**: 해당 ID의 주문 데이터가 존재하지 않을 경우 조회를 거부하고 "존재하지 않는 주문입니다" 안내를 노출한다
