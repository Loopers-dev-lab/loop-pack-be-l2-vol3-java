# 회원(User)

## User Scenario

- **비회원**: 서비스에 가입하여 회원이 될 수 있다
- **회원**: 자신의 정보를 조회하고, 비밀번호를 변경할 수 있다

## Feature List

| ID | 기능 명칭 | 대상 | 인증 | API | 설명 |
| --- | --- | --- | --- | --- | --- |
| US-01 | 회원가입 | User | 불필요 | POST /api/v1/users | 신규 사용자 계정 생성 |
| US-02 | 내 정보 조회 | User | 필요 | GET /api/v1/users/me | 본인 회원 정보 확인 |
| US-03 | 비밀번호 수정 | User | 필요 | PATCH /api/v1/users/me/password | 본인 비밀번호 변경 |

## Business Rule

| 규칙 | 설명 |
| --- | --- |
| loginId 유일성 | loginId는 중복할 수 없다 |
| loginId 변경 불가 | 회원가입 후 loginId는 변경할 수 없다 |
| 비밀번호 암호화 | 비밀번호는 암호화하여 저장한다 |
| 비밀번호 생년월일 불포함 | 비밀번호에 생년월일을 포함할 수 없다 (yyyyMMdd, yyMMdd, MMdd 형식) |
| 이름 마스킹 | 이름은 응답 시 마지막 글자를 `*`로 대체하여 반환한다 (1글자 이름은 전체 `*`) |
| 이메일 유일성 미적용 | 이메일 중복 체크를 하지 않는다 |
| 비밀번호 변경 시 동일 불가 | 새 비밀번호는 현재 비밀번호와 달라야 한다 |

## Use Case Flow

### [US-01] 회원가입

- **Main Flow**
    1. 비회원이 회원 정보를 입력하고 가입을 요청한다
    2. loginId의 중복 여부를 확인한다
    3. 비밀번호를 암호화하여 회원을 생성한다
- **Exception Flow**
    - **[loginId 중복]**: 이미 사용 중인 loginId일 경우 가입을 거부하고 "이미 사용 중인 로그인 ID입니다" 안내를 노출한다

### [US-02] 내 정보 조회

- **Precondition**
    - 회원가입이 완료된 회원이어야 한다
- **Main Flow**
    1. 회원이 내 정보 조회를 요청한다
    2. 인증 정보를 확인한다
    3. 본인의 회원 정보를 마스킹 처리하여 반환한다
- **Exception Flow**
    - **[인증 실패]**: 인증 정보가 유효하지 않을 경우 조회를 거부하고 "인증에 실패했습니다" 안내를 노출한다

### [US-03] 비밀번호 수정

- **Precondition**
    - 회원가입이 완료된 회원이어야 한다
- **Main Flow**
    1. 회원이 새 비밀번호를 입력하고 변경을 요청한다
    2. 인증 정보를 확인한다
    3. 새 비밀번호가 현재 비밀번호와 다른지 확인한다
    4. 비밀번호를 암호화하여 변경한다
- **Exception Flow**
    - **[인증 실패]**: 인증 정보가 유효하지 않을 경우 변경을 거부하고 "인증에 실패했습니다" 안내를 노출한다
    - **[동일 비밀번호]**: 새 비밀번호가 현재 비밀번호와 같을 경우 변경을 거부하고 "현재 비밀번호와 동일한 비밀번호는 사용할 수 없습니다" 안내를 노출한다
