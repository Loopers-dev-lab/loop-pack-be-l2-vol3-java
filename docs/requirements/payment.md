# 결제

## User Scenario

- 사용자: 주문에 대해 카드 결제를 요청하고, 결제 진행 상태를 확인하며, 결제가 완료되면 주문이 확정된다
- 시스템: PG(결제대행사) 시스템과 비동기로 연동하여 결제를 처리하고, 장애 상황에서도 안정적으로 동작한다

## Feature List

| ID | 기능 명칭 | 대상 | 인증 | API | 설명 |
| --- | --- | --- | --- | --- | --- |
| PM-01 | 결제 요청 | User | 필요 | POST /api/v1/payments | 주문에 대한 PG 카드 결제 요청 |
| PM-02 | 결제 콜백 수신 | System | 불필요 | POST /api/v1/payments/callback | PG 처리 결과 콜백 수신 및 상태 확정 |
| PM-03 | 결제 상세 조회 | User | 필요 | GET /api/v1/payments/{paymentId} | 단일 결제 상태 확인 |
| PM-04 | 주문별 결제 조회 | User | 필요 | GET /api/v1/orders/{orderId}/payment | 주문에 연결된 결제 정보 조회 |
| PM-05 | 결제 상태 수동 확인 | User | 필요 | POST /api/v1/payments/{paymentId}/verify | PG 조회 API를 통한 결제 상태 수동 확정 |

## Business Rule

| 규칙 | 설명 |
| --- | --- |
| 1주문 1결제 | 하나의 주문에 성공(SUCCESS) 또는 보류(REQUESTED/PENDING) 상태의 결제가 존재하면 추가 결제를 요청할 수 없다 |
| 재결제 허용 | 결제가 실패(FAILED)한 주문은 다시 결제를 요청할 수 있다 |
| PENDING 주문만 결제 가능 | 결제는 주문 상태가 PENDING인 경우에만 요청할 수 있다 |
| 결제 금액 자동 산정 | 결제 금액은 주문의 최종 결제 금액(finalAmount)을 사용한다 |
| 결제 실패 시 주문 유지 | PG 콜백으로 결제 실패가 확정되어도 주문 상태는 PENDING을 유지하며, 재고와 쿠폰도 유지된다 |
| 결제 성공 시 주문 확정 | PG 콜백으로 결제 성공이 확정되면 주문 상태를 PAID로 전이한다 |
| 비동기 결제 처리 | PG 시스템은 결제 요청을 접수 후 비동기로 처리하며, 처리 완료 시 콜백으로 결과를 전달한다 |
| 타임아웃 시 보류 처리 | PG 요청이 타임아웃되면 결제를 즉시 실패 처리하지 않고 보류(REQUESTED) 상태를 유지한다 (PG에서 처리되었을 수 있으므로) |
| PG 요청 실패 시 즉시 실패 | PG 요청 자체가 실패(서버 에러 등)하면 결제를 FAILED 처리하고 사용자에게 에러를 반환한다 |
| 콜백 멱등성 | 동일한 콜백이 중복 수신되어도 이미 확정된 결제는 재처리하지 않는다 |
| 본인 결제만 조회 | 사용자는 본인의 결제만 조회할 수 있으며, 타인의 결제 접근 시 미존재로 응답한다 |
| 외부 시스템 장애 보호 | 서킷 브레이커를 적용하여 PG 장애가 내부 시스템으로 전파되지 않도록 보호한다 |

## Use Case Flow

### [PM-01] 결제 요청

- **Precondition**
    - 해당 주문이 존재하고 PENDING 상태여야 한다
    - 해당 주문이 본인의 주문이어야 한다
    - 해당 주문에 성공 또는 보류 상태의 결제가 없어야 한다
- **Main Flow**
    1. 사용자가 주문 ID, 카드 종류, 카드 번호를 입력하고 결제를 요청한다
    2. 주문의 존재 여부와 소유권을 확인한다
    3. 주문 상태가 PENDING인지 확인한다
    4. 해당 주문에 진행 중이거나 성공한 결제가 없는지 확인한다
    5. 결제 정보를 생성(REQUESTED)하고 저장한다
    6. PG 시스템에 결제를 요청한다
    7. PG가 접수하면 결제 상태를 PENDING으로 변경한다
    8. 결제 접수 정보를 반환한다
- **Alternate Flow**
    - **[PG 타임아웃]**: PG 응답이 타임아웃되면 결제 상태를 REQUESTED로 유지하고, 사용자에게 "결제 처리 중입니다. 잠시 후 결제 상태를 확인해주세요" 안내를 노출한다
- **Exception Flow**
    - **[주문 미존재]**: 해당 주문이 존재하지 않거나 본인의 주문이 아닌 경우 "존재하지 않는 주문입니다" 안내를 노출한다
    - **[주문 상태 불가]**: 주문 상태가 PENDING이 아닌 경우 "결제할 수 없는 주문 상태입니다" 안내를 노출한다
    - **[결제 중복]**: 해당 주문에 이미 진행 중이거나 성공한 결제가 있는 경우 "이미 결제가 진행 중이거나 완료된 주문입니다" 안내를 노출한다
    - **[PG 요청 실패]**: PG 시스템 요청 자체가 실패한 경우 결제를 FAILED 처리하고 "결제 요청에 실패했습니다. 잠시 후 다시 시도해주세요" 안내를 노출한다
    - **[서킷 브레이커 오픈]**: PG 장애로 서킷이 열린 경우 "현재 결제 서비스를 이용할 수 없습니다. 잠시 후 다시 시도해주세요" 안내를 노출한다

### [PM-02] 결제 콜백 수신

- **Precondition**
    - PG 시스템이 결제 처리를 완료하고 콜백을 전송해야 한다
- **Main Flow**
    1. PG 시스템이 결제 처리 결과(transactionKey, 상태, 사유)를 콜백으로 전달한다
    2. transactionKey로 결제 정보를 조회한다
    3. 결제가 이미 확정 상태인지 확인한다 (멱등성)
    4. PG 결과가 성공이면 결제를 SUCCESS로 변경하고, 주문을 PAID로 전이한다
    5. PG 결과가 실패이면 결제를 FAILED로 변경한다 (주문은 PENDING 유지)
- **Alternate Flow**
    - **[중복 콜백]**: 이미 확정된 결제에 대한 콜백이면 무시하고 정상 응답한다
- **Exception Flow**
    - **[결제 미존재]**: transactionKey에 해당하는 결제가 없으면 무시한다

### [PM-03] 결제 상세 조회

- **Main Flow**
    1. 사용자가 결제 ID로 상세 정보 조회를 요청한다
    2. 결제 존재 여부와 소유권을 확인한다
    3. 결제 상태, 카드 정보, 금액 등을 반환한다
- **Exception Flow**
    - **[결제 미존재]**: 해당 결제가 존재하지 않거나 본인의 결제가 아닌 경우 "존재하지 않는 결제입니다" 안내를 노출한다

### [PM-04] 주문별 결제 조회

- **Main Flow**
    1. 사용자가 주문 ID로 연결된 결제 정보 조회를 요청한다
    2. 주문 존재 여부와 소유권을 확인한다
    3. 해당 주문에 연결된 결제 정보를 반환한다
- **Alternate Flow**
    - **[결제 없음]**: 주문에 연결된 결제가 없으면 빈 응답을 반환한다
- **Exception Flow**
    - **[주문 미존재]**: 해당 주문이 존재하지 않거나 본인의 주문이 아닌 경우 "존재하지 않는 주문입니다" 안내를 노출한다

### [PM-05] 결제 상태 수동 확인

- **Precondition**
    - 결제 상태가 REQUESTED 또는 PENDING이어야 한다 (미확정 상태)
- **Main Flow**
    1. 사용자가 결제 ID로 상태 확인을 요청한다
    2. 결제 존재 여부와 소유권을 확인한다
    3. 결제가 미확정 상태인지 확인한다
    4. PG 조회 API를 호출하여 실제 결제 상태를 확인한다
    5. PG 결과에 따라 결제 상태를 확정하고, 성공 시 주문을 PAID로 전이한다
    6. 확정된 결제 정보를 반환한다
- **Alternate Flow**
    - **[PG에 결제 정보 없음]**: PG에서 해당 거래를 찾을 수 없으면 결제를 FAILED로 처리한다
- **Exception Flow**
    - **[결제 미존재]**: 해당 결제가 존재하지 않거나 본인의 결제가 아닌 경우 "존재하지 않는 결제입니다" 안내를 노출한다
    - **[이미 확정]**: 이미 SUCCESS 또는 FAILED 상태인 결제에 대해 "이미 확정된 결제입니다" 안내를 노출한다
    - **[PG 조회 실패]**: PG 조회 API 호출이 실패하면 "결제 상태를 확인할 수 없습니다. 잠시 후 다시 시도해주세요" 안내를 노출한다
