# 브랜드(Brand)

## User Scenario

- **사용자**: 브랜드 정보를 확인할 수 있다
- **관리자**: 입점 **브랜드의 정보를 관리**하여 서비스의 데이터를 최신으로 유지한다

## Feature List

| ID | 기능 명칭 | 대상 | 인증 | API | 설명 |
| --- | --- | --- | --- | --- | --- |
| BR-01 | 브랜드 등록 | Admin | LDAP | POST /api-admin/v1/brands | 새로운 입점 브랜드 정보 생성 |
| BR-02 | 브랜드 정보 수정 | Admin | LDAP | PATCH /api-admin/v1/brands/{brandId} | 브랜드 정보 변경 |
| BR-03 | 브랜드 삭제 | Admin | LDAP | DELETE /api-admin/v1/brands/{brandId} | 브랜드 운영 종료 및 하위 상품 노출 차단 |
| BR-04 | 브랜드 목록 조회 | Admin | LDAP | GET /api-admin/v1/brands | 관리용 전체 브랜드 리스트 (페이징) |
| BR-05 | 브랜드 상세 조회 | Admin | LDAP | GET /api-admin/v1/brands/{brandId} | 관리용 브랜드 상세 정보 확인 |
| BR-06 | 브랜드 목록 조회 | User | 불필요 | GET /api/v1/brands | 고객용 활성 브랜드 리스트 |
| BR-07 | 브랜드 정보 조회 | User | 불필요 | GET /api/v1/brands/{brandId} | 고객용 브랜드 프로필 정보 |

## Business Rule

| 규칙 | 설명 |
| --- | --- |
| 삭제 데이터 관리 | 어드민은 삭제된 브랜드도 조회할 수 있다 |
| 삭제 데이터 노출 차단 | 사용자에게는 활성 브랜드만 노출한다 |
| 브랜드명 유일성 | 브랜드명은 삭제 여부와 관계없이 중복할 수 없다 |
| 브랜드 삭제 연쇄 | 브랜드 삭제 시 해당 브랜드에 속한 모든 상품도 삭제 상태로 변경한다 |

## Use Case Flow

### [BR-01] 브랜드 등록

- **Main Flow**
    1. 관리자가 등록할 브랜드 정보를 입력하고 등록을 요청한다
    2. 브랜드명의 중복 여부를 확인한다
    3. 새로운 브랜드를 활성 상태로 저장한다
- **Exception Flow**
    - **[브랜드명 중복 발생]**: 이미 존재하는 브랜드명일 경우 등록을 거부하고 "이미 등록된 브랜드입니다" 안내를 노출한다

### [BR-02] 브랜드 정보 수정

- **Main Flow**
    1. 관리자가 수정할 브랜드를 선택하고 정보 수정을 요청한다
    2. 해당 브랜드의 존재 여부를 확인한다
    3. 브랜드명 변경 시, 다른 브랜드와의 중복 여부를 확인한다
    4. 브랜드 정보를 수정한다
- **Exception Flow**
    - **[브랜드 미존재]**: 브랜드가 미존재할 경우 수정을 거부하고 "존재하지 않는 브랜드입니다" 안내를 노출한다
    - **[브랜드명 중복 발생]**: 이미 존재하는 브랜드명일 경우 수정을 거부하고 "이미 등록된 브랜드입니다" 안내를 노출한다

### [BR-03] 브랜드 삭제

- **Main Flow**
    1. 관리자가 삭제할 브랜드를 선택하고 삭제를 요청한다
    2. 해당 브랜드의 존재 여부를 확인한다
    3. 해당 브랜드를 삭제 상태로 변경한다
    4. 해당 브랜드에 속한 모든 상품도 삭제 상태로 변경한다
- **Exception Flow**
    - **[브랜드 미존재]**: 브랜드가 미존재할 경우 삭제를 거부하고 "존재하지 않는 브랜드입니다" 안내를 노출한다

### [BR-04] 브랜드 목록 조회 (Admin)

- **Main Flow**
    1. 관리자가 브랜드 목록 조회를 요청한다
    2. 전체 브랜드를 최신 등록순으로 페이징하여 반환한다
- **Alternate Flow**
    - **[브랜드명 검색]**: 브랜드명 키워드로 검색하여 반환한다
    - **[상태 필터]**: 활성/삭제 상태별로 필터링하여 반환한다

### [BR-05] 브랜드 상세 조회 (Admin)

- **Main Flow**
    1. 관리자가 조회할 브랜드를 선택하여 상세 정보 조회를 요청한다
    2. 해당 브랜드의 데이터 존재 여부를 확인한다
    3. 해당 브랜드의 기본 정보와 관리용 데이터를 반환한다
- **Alternate Flow**
    - **[삭제된 브랜드]**: 삭제 상태의 브랜드도 조회 가능하며, 삭제 상태임을 표시하여 반환한다
- **Exception Flow**
    - **[브랜드 데이터 없음]**: 해당 ID의 브랜드 데이터가 존재하지 않을 경우 조회를 거부하고 "존재하지 않는 브랜드입니다" 안내를 노출한다

### [BR-06] 브랜드 목록 조회 (User)

- **Main Flow**
    1. 사용자가 브랜드 목록 조회를 요청한다
    2. 활성 브랜드만 이름 오름차순으로 페이징하여 반환한다
- **Alternate Flow**
    - [브랜드명 검색]: 브랜드명 키워드로 검색하여 반환한다

### [BR-07] 브랜드 정보 조회 (User)

- **Main Flow**
    1. 사용자가 조회할 브랜드를 선택하고 브랜드 정보 조회를 요청한다
    2. 해당 브랜드의 존재 여부를 확인한다
    3. 해당 브랜드의 기본 정보를 반환한다
- **Exception Flow**
    - [브랜드 미존재]: 브랜드가 미존재할 경우 조회를 거부하고 "존재하지 않는 브랜드입니다" 안내를 노출한다
