# 재고

## User Scenario

- 시스템: 주문 생성 시 재고를 점유하고, 결제 성공 시 점유를 확정하며, 결제 실패/취소 시 점유를 해제하여 재고 정합성을 보장한다
- 시스템: 주기적으로 상태 불일치를 탐지하고 보정하여 점유 누수를 방지한다

## Business Rule

| 규칙 | 설명 |
| --- | --- |
| 재고 도메인 독립 | 재고는 상품과 별도의 도메인으로 관리하며, 상품 ID로 연결한다 |
| 점유/확정 모델 | 재고는 점유(reserve) → 확정(confirm) 또는 해제(release) 생명주기를 가진다 |
| 점유 가능 조건 | 현재 재고(총 재고 - 점유 수량 - 확정 차감 수량)가 주문 수량 이상이어야 점유할 수 있다 |
| 전체 실패 | 주문 상품 중 하나라도 점유할 수 없으면 전체 점유가 실패한다 |
| 확정 시 점유 차감 | 확정 시 점유 수량을 줄이고, 확정 차감 수량을 늘린다 (총 재고 변화 없음) |
| 해제 시 점유 복원 | 해제 시 점유 수량을 줄여 가용 재고를 복원한다 |
| 보정 대상 | 주문이 취소(CANCELED)되었으나 점유가 남아있는 경우, 또는 결제가 확정되었으나 재고가 미확정인 경우를 탐지한다 |
| 보정 주기 | 스케줄러가 N분마다 실행하여 불일치를 보정한다 (주기는 설정 가능) |

## Use Case Flow

### [ST-01] 재고 점유

- **Precondition**
    - 주문 상품이 모두 존재해야 한다
    - 각 상품의 가용 재고가 주문 수량 이상이어야 한다
- **Main Flow**
    1. 주문 생성 요청이 들어오면 주문 상품 목록의 재고를 조회한다
    2. 각 상품의 가용 재고(총 재고 - 점유 수량 - 확정 차감 수량)가 주문 수량 이상인지 확인한다
    3. 모든 상품의 재고가 충분하면 주문 수량만큼 점유 수량을 증가시킨다
    4. 점유된 재고 정보를 반환한다
- **Exception Flow**
    - **[재고 부족]**: 상품의 가용 재고가 주문 수량 미만인 경우 전체 점유를 거부하고 "재고가 부족한 상품이 있습니다" 안내를 노출한다
    - **[재고 미존재]**: 해당 상품의 재고 정보가 존재하지 않는 경우 점유를 거부하고 "재고 정보가 존재하지 않습니다" 안내를 노출한다

### [ST-02] 재고 확정

- **Precondition**
    - 해당 주문의 재고가 점유 상태여야 한다
- **Main Flow**
    1. 결제가 성공하면 해당 주문의 점유 재고를 조회한다
    2. 점유 수량을 줄이고 확정 차감 수량을 늘린다
    3. 재고 확정을 완료한다

### [ST-03] 재고 해제

- **Precondition**
    - 해당 주문의 재고가 점유 또는 확정 상태여야 한다
- **Main Flow (점유 해제)**
    1. 결제가 실패하면 해당 주문의 점유 재고를 조회한다
    2. 점유 수량을 줄여 가용 재고를 복원한다
    3. 재고 해제를 완료한다
- **Main Flow (확정 복원)**
    1. 결제가 취소되면 해당 주문의 확정 재고를 조회한다
    2. 확정 차감 수량을 줄여 가용 재고를 복원한다
    3. 재고 복원을 완료한다

### [ST-04] 재고 보정

- **Main Flow**
    1. 스케줄러가 주기적으로 상태 불일치 탐지를 실행한다
    2. 주문이 CANCELED 상태인데 점유가 남아있는 건을 조회한다
    3. 해당 점유를 해제하여 가용 재고를 복원한다
    4. 결제가 성공(SUCCEEDED)인데 재고가 미확정인 건을 조회한다
    5. 해당 재고를 확정 처리한다
    6. 보정 결과를 로그로 기록한다
