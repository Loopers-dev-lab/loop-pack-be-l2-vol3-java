# 쿠폰

## User Scenario

- 관리자: 할인 쿠폰 템플릿을 등록/수정/삭제하고, 발급 현황을 관리한다
- 사용자: 쿠폰을 발급받고, 보유 쿠폰 목록을 확인하며, 주문 시 쿠폰을 적용해 할인받는다

## Feature List

| --- | --- | --- | --- | --- | --- |

## Business Rule

| 규칙 | 설명 |
| --- | --- |
| 쿠폰 유형 | 정액(FIXED): 고정 금액 할인, 정률(RATE): 주문 금액의 퍼센트 할인 |
| 쿠폰 상태 | AVAILABLE(사용 가능), USED(사용 완료), EXPIRED(기한 만료) |
| 만료 판정 | 만료일(expiredAt) 기준으로 조회 시점에 동적으로 판정한다. 별도 상태 전환 없이 만료일이 지나면 EXPIRED로 취급한다 |
| 쿠폰 사용 시점 | 주문 성공 시 AVAILABLE → USED로 전환된다 |
| 재사용 불가 | 사용된 쿠폰은 재사용할 수 없다 |
| 1인 1매 | 동일 쿠폰 템플릿당 사용자 1인 1매만 발급 가능하다 |
| 발급 수량 제한 | 쿠폰 템플릿에 설정된 총 발급 수량을 초과하여 발급할 수 없다 |
| 만료 쿠폰 발급 불가 | 만료일이 지난 쿠폰은 신규 발급할 수 없다 |
| 삭제 쿠폰 발급 불가 | 삭제된 쿠폰 템플릿은 발급할 수 없다 |
| 연쇄 삭제 | 쿠폰 템플릿 삭제 시 미사용(AVAILABLE) 발급 쿠폰도 함께 삭제한다. 이미 사용된(USED) 쿠폰은 보존한다 |
| 최소 주문 금액 | 쿠폰에 최소 주문 금액이 설정된 경우, 주문 금액이 조건을 충족해야 적용할 수 있다 (선택 항목) |
| 정률 할인 상한 없음 | 정률(RATE) 쿠폰의 할인 금액에 별도 상한이 없다 |
| 동시성 보장 | 발급 수량 차감과 중복 발급 체크는 동시 요청에도 정합성이 보장되어야 한다 |

## Use Case Flow

### [CP-01] 쿠폰 등록

- **Main Flow**
    1. 관리자가 쿠폰 정보(이름, 유형, 할인값, 최소 주문 금액, 총 발급 수량, 만료일)를 입력하고 등록을 요청한다
    2. 쿠폰 템플릿을 등록한다
- **Exception Flow**
    - **[필수 항목 누락]**: 이름, 유형, 할인값, 총 발급 수량, 만료일 중 하나라도 누락되면 등록을 거부하고 "필수 항목이 누락되었습니다" 안내를 노출한다
    - **[유효하지 않은 할인값]**: 할인값이 0 이하이거나, 정률(RATE) 쿠폰의 할인값이 100을 초과하면 등록을 거부하고 "유효하지 않은 할인값입니다" 안내를 노출한다
    - **[만료일이 과거]**: 만료일이 현재보다 과거이면 등록을 거부하고 "만료일은 현재 이후여야 합니다" 안내를 노출한다

### [CP-02] 쿠폰 수정

- **Main Flow**
    1. 관리자가 수정할 쿠폰을 선택하고 수정 정보를 입력하여 수정을 요청한다
    2. 해당 쿠폰의 존재 여부를 확인한다
    3. 쿠폰 정보를 수정한다
- **Exception Flow**
    - **[쿠폰 미존재]**: 해당 ID의 쿠폰 데이터가 존재하지 않거나 삭제 상태인 경우 수정을 거부하고 "존재하지 않는 쿠폰입니다" 안내를 노출한다
    - **[유효하지 않은 할인값]**: CP-01과 동일
    - **[만료일이 과거]**: CP-01과 동일

### [CP-03] 쿠폰 삭제

- **Main Flow**
    1. 관리자가 삭제할 쿠폰을 선택하고 삭제를 요청한다
    2. 해당 쿠폰의 존재 여부를 확인한다
    3. 쿠폰 템플릿을 삭제한다
    4. 해당 쿠폰의 미사용(AVAILABLE) 발급 쿠폰을 함께 삭제한다
- **Exception Flow**
    - **[쿠폰 미존재]**: 해당 ID의 쿠폰 데이터가 존재하지 않거나 삭제 상태인 경우 삭제를 거부하고 "존재하지 않는 쿠폰입니다" 안내를 노출한다

### [CP-04] 쿠폰 목록 조회 (Admin)

- **Main Flow**
    1. 관리자가 쿠폰 목록 조회를 요청한다
    2. 활성 쿠폰 템플릿을 최신순으로 페이징하여 반환한다

### [CP-05] 쿠폰 상세 조회 (Admin)

- **Main Flow**
    1. 관리자가 조회할 쿠폰을 선택하고 상세 정보 조회를 요청한다
    2. 해당 쿠폰의 존재 여부를 확인한다
    3. 쿠폰 템플릿 상세 정보를 반환한다
- **Exception Flow**
    - **[쿠폰 미존재]**: 해당 ID의 쿠폰 데이터가 존재하지 않거나 삭제 상태인 경우 조회를 거부하고 "존재하지 않는 쿠폰입니다" 안내를 노출한다

### [CP-06] 쿠폰 발급 내역 조회 (Admin)

- **Main Flow**
    1. 관리자가 특정 쿠폰의 발급 내역 조회를 요청한다
    2. 해당 쿠폰의 존재 여부를 확인한다
    3. 발급 내역을 최신순으로 페이징하여 반환한다 (사용자 정보, 발급 일시, 사용 상태 포함)
- **Exception Flow**
    - **[쿠폰 미존재]**: 해당 ID의 쿠폰 데이터가 존재하지 않거나 삭제 상태인 경우 조회를 거부하고 "존재하지 않는 쿠폰입니다" 안내를 노출한다

### [CP-07] 쿠폰 발급

- **Precondition**
    - 사용자가 로그인되어 있어야 한다
- **Main Flow**
    1. 사용자가 쿠폰 발급을 요청한다
    2. 해당 쿠폰의 존재 여부를 확인한다
    3. 발급 가능 여부(만료, 수량, 중복)를 확인한다
    4. 쿠폰을 발급한다
- **Exception Flow**
    - **[쿠폰 미존재]**: 해당 ID의 쿠폰 데이터가 존재하지 않거나 삭제 상태인 경우 발급을 거부하고 "존재하지 않는 쿠폰입니다" 안내를 노출한다
    - **[만료된 쿠폰]**: 만료일이 지난 쿠폰에 대해 발급을 거부하고 "만료된 쿠폰입니다" 안내를 노출한다
    - **[발급 수량 초과]**: 총 발급 수량이 모두 소진된 경우 발급을 거부하고 "발급 가능 수량이 모두 소진되었습니다" 안내를 노출한다
    - **[중복 발급]**: 이미 해당 쿠폰을 발급받은 사용자가 다시 요청한 경우 발급을 거부하고 "이미 발급받은 쿠폰입니다" 안내를 노출한다

### [CP-08] 내 쿠폰 목록 조회

- **Precondition**
    - 사용자가 로그인되어 있어야 한다
- **Main Flow**
    1. 사용자가 보유 쿠폰 목록 조회를 요청한다
    2. 사용자의 발급 쿠폰을 최신 발급순으로 반환한다 (쿠폰 정보, 사용 상태 포함)
