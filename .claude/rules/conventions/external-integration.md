# 외부 시스템 통합

## 원칙

도메인이 외부 시스템을 직접 알지 않는다. 외부 시스템의 장애가 내 시스템 전체를 멈추게 하지 않는다.

## 어댑터 패턴

- 도메인 인터페이스는 `domain/`에 정의하고, 외부 시스템 구현체는 `infrastructure/`에 배치한다
- 어댑터 전용 DTO(Command/Result)는 도메인 인터페이스와 함께 `domain/`에 정의한다
- 외부 API의 DTO를 application 계층 위로 노출하지 않는다
- 외부 API 응답을 도메인 Entity에 직접 매핑하지 않는다

## 예외 변환

외부 시스템의 예외를 그대로 전파하면 도메인이 외부에 결합된다. 반드시 도메인 수준 예외로 감싸서 전달한다.

| 상황 | 전략 |
|------|------|
| 외부 통신 실패 유형 구분이 비즈니스 분기에 영향을 줄 때 | 도메인 특화 예외 계층 정의 (타임아웃, 통신 오류, 비즈니스 거절 등) |
| 단순 성공/실패만 판단하면 될 때 | CoreException으로 충분 |

- 외부 API의 에러 코드/메시지를 사용자에게 그대로 노출하지 않는다

## 결과 표현

외부 호출이 여러 결과 경로(성공, 실패, 타임아웃, 서비스 불가 등)를 가질 때:

- **예외로 흐름을 제어하지 않는다** — 예외는 예외적 상황에만 사용
- sealed interface로 모든 결과 경로를 명시적으로 표현하여 **컴파일러가 처리를 강제**한다
- 호출자(Facade)는 switch-case로 모든 경우를 처리한다

```java
public sealed interface XxxOutcome {
    record Success(...) implements XxxOutcome {}
    record Failed(String reason) implements XxxOutcome {}
    record Timeout() implements XxxOutcome {}
    // 컴파일러가 모든 케이스 처리를 강제
}
```

## 트랜잭션 격리

- 외부 API 호출은 트랜잭션 안에 포함하지 않는다
- DB 작업과 외부 호출을 분리한다: 트랜잭션 커밋 후 외부 호출, 또는 TransactionTemplate으로 경계를 명시적으로 분리
- 외부 호출 실패 시 보상 트랜잭션이 필요한지 판단한다

## 복원력(Resilience)

외부 시스템 장애로부터 내 시스템을 보호한다.

### 코드 레벨에서 핸들링 가능한 것

- 타임아웃 설정
- 폴백 처리 (장애 시 대체 동작)
- 예외 유형별 분기 (재시도 가능 여부 판단)

### 코드 레벨로 결정할 수 없는 것

- Circuit Breaker threshold (실패율, 슬로우콜 비율)
- 동시 호출 수 제한값 (Bulkhead)
- 재시도 횟수와 간격

이러한 값은 실제 트래픽, 장애 가능성, 인프라 구성을 기반으로 운영 데이터에서 결정한다.

## 하지 말아야 할 것

- 외부 API 응답을 도메인 Entity에 직접 매핑하지 않는다
- 외부 API의 DTO를 application 계층 위로 노출하지 않는다
- 외부 API 호출을 긴 트랜잭션 안에 넣지 않는다
- 외부 API의 에러 코드/메시지를 사용자에게 그대로 노출하지 않는다
- 외부 시스템의 가용성을 가정하지 않는다 — 항상 실패할 수 있다고 전제한다
