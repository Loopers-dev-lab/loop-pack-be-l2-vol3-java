커밋을 수행할 때 반드시 다음 흐름을 따른다.

### 1️⃣ 변경 사항을 분석한다
- `git status`로 변경된 파일, 미추적 파일을 확인한다.
- `git diff`(unstaged)와 `git diff --cached`(staged)로 변경 내용을 파악한다.
- 최근 커밋 메시지 3~5개를 `git log --oneline -5`로 확인하여 메시지 스타일을 참고한다.

> **근거**: 변경 파일과 내용을 정확히 파악해야 올바른 prefix를 결정하고, 민감 파일(.env, credentials 등)을 사전에 차단할 수 있다.

### 2️⃣ 테스트를 실행한다
- `./gradlew :apps:commerce-api:test`를 실행하여 commerce-api 테스트가 통과하는지 확인한다.
- 테스트가 실패하면:
  - 실패한 테스트와 에러 메시지를 사용자에게 보여준다
  - 커밋을 중단한다
  - 테스트 수정을 먼저 진행하도록 안내한다
- 테스트가 모두 통과하면 다음 단계로 진행한다.

> **근거**: CLAUDE.md의 커밋 전제조건 — "Only commit when ALL tests are passing". Green 상태에서만 커밋하는 TDD 원칙을 강제한다.

### 3️⃣ 커밋 prefix를 결정한다
- 변경 내용을 기반으로 적절한 prefix를 추천한다:
  - `refactor:` — 동작 변경 없이 코드 구조만 변경한 경우
  - `feat:` — 새로운 기능을 추가한 경우
  - `fix:` — 버그를 수정한 경우
  - `test:` — 테스트만 추가/수정한 경우
  - `docs:` — 문서만 변경한 경우
- 추천 결과를 사용자에게 보여주고 확인/수정 기회를 제공한다.

> **근거**: CLAUDE.md에 정의된 5가지 prefix를 변경 내용 분석 기반으로 자동 추천한다. 단, 의도와 맥락은 사용자만이 판단할 수 있으므로 최종 결정권은 사용자에게 둔다.

### 4️⃣ 파일을 스테이징한다
- 커밋 대상 파일을 `git add <파일명>` 형태로 개별 스테이징한다.
- **절대 `git add -A`나 `git add .`를 사용하지 않는다.**
- 다음 파일이 포함되어 있으면 경고하고 스테이징에서 제외한다:
  - `.env`, `.env.*`
  - `credentials.*`, `*secret*`
  - 기타 민감 정보가 포함될 수 있는 파일

> **근거**: `git add -A`는 의도하지 않은 파일(민감 정보, 바이너리, 임시 파일)을 포함할 위험이 있다. 명시적 파일 지정이 안전하다.

### 5️⃣ 커밋 메시지를 작성한다
- 형식: `{prefix} {변경 요약}`
- 변경 요약은 한국어로, "무엇을 왜 변경했는지"가 드러나도록 작성한다.
- HEREDOC 형식을 사용하여 포맷팅을 보장한다.
- Co-Authored-By 트레일러를 포함한다.

```bash
git commit -m "$(cat <<'EOF'
{prefix} {변경 요약}

Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>
EOF
)"
```

> **근거**: HEREDOC은 멀티라인 커밋 메시지의 포맷팅을 안정적으로 보장한다. Co-Authored-By는 AI 협업 이력을 투명하게 남긴다.

### 6️⃣ 커밋을 실행하고 결과를 확인한다
- 최종 커밋 메시지와 스테이징된 파일 목록을 사용자에게 보여주고 확인을 받는다.
- 확인 후 커밋을 실행한다.
- 커밋 후 `git status`로 정상 처리되었는지 검증한다.
- 커밋 해시와 메시지를 사용자에게 보고한다.

> **근거**: 커밋은 되돌리기 번거로운 작업이므로 실행 전 사용자 확인을 거친다. 실행 후 검증으로 의도대로 처리되었는지 보장한다.

### 톤 & 스타일 가이드
- CLAUDE.md의 커밋 규칙을 근거로 제시하며, 왜 이렇게 하는지 설명한다
- 규칙 위반 시 강제 차단이 아닌 경고 + 대안 제시 방식을 취한다
- 사용자의 의도를 존중하되, 규칙 위반이 명확한 경우 반드시 알린다
