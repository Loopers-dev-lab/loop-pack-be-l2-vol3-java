## 오류 수정 시 문서화 규칙

오류를 수정할 때는 반드시 아래 형식으로 기록한다.
기록 위치: `.claude/plan.md`의 "오류 수정 이력" 섹션

### 필수 항목

| 항목 | 설명 |
|------|------|
| **AS-IS** | 수정 전 코드 (문제가 되는 부분만 발췌) |
| **TO-BE** | 수정 후 코드 |
| **왜 (Why)** | 왜 이 수정이 필요한지 (기술적 원인) |
| **동작 원리** | 내부적으로 어떻게 동작하는지 (Java/Spring 메커니즘 설명) |
| **검증 테스트** | 수정이 올바른지 확인하는 테스트 코드 |

### 항목 번호 규칙

- 순번은 `[#N]` 형식으로 누적 부여한다 (예: `[#1]`, `[#2]`, ...)
- 출처(리뷰어, 본인 발견 등)를 명시한다
- plan.md의 기존 이력 다음 번호로 이어간다

### 작성 형식

```markdown
### [#N] 오류 제목

**출처**: (CodeRabbit 리뷰 / 본인 발견 / 코드 리뷰 등)

#### AS-IS
```java
// 수정 전 코드
```

#### TO-BE
```java
// 수정 후 코드
```

#### 왜 (Why)
기술적 원인 설명

#### 동작 원리
Java/Spring 내부 메커니즘 설명

#### 검증 테스트
```java
@Test
void 검증_테스트() { ... }
```
```

### 기존 이력 참조

현재까지 기록된 오류 수정 이력:
- `[#1]` CoreException 예외 원인(cause) 유실 문제
- `[#2]` BCryptPasswordEncryptor null 입력 처리 문제
- 다음 번호: `[#3]`부터 시작
