**상황**
- `$ARGUMENTS/04-decisions.md` 에 확정된 설계 판단을 기반으로 과제 구현을 진행한다.
- `$ARGUMENTS/00-requirements.md` 의 요구사항을 100% 만족시키는 것이 목표다.

**목표**
- `$ARGUMENTS/04-decisions.md` 에 따라서 과제 구현을 진행한다.
- `$ARGUMENTS/00-requirements.md` 를 100% 만족하도록 구현을 진행한다.
- 각 step별로 구현이 끝나면 '검증'을 진행한다.
- 최종적으로 검토가 다 끝났다면, 다시한번 `$ARGUMENTS/00-requirements.md` 를 100% 만족시키는지, 각 레이어별 책임/역할을 100% 지키고 있는지, 간단한 방법으로도 요구사항을 100% 만족시킬 수 있는데 지나치게 복잡도를 높여서 구현하여 사이드이펙트를 발생시킨 부분은 없는지, 모든 회귀테스트를 잘 통과하는지, 누락된 테스트코드가 없는지, 개발에 필요한 모든 규칙문서/skills/CLAUDE.md 등을 만족하는지 등을 꼼꼼하게 재검토 진행한다. 이때 해당 내용을 codex를 호출하여 똑같이 검토를 진행하고, 너와 codex 결과 두 개를 교차검증(codex에게도 네 검토결과를 넘겨주고 평가받아야함)하여 수정해야할 부분을 수정한다.

**검증**
- codex를 호출하여 충분한 맥락이 포함된 프롬프트를 전달하여 검증을 진행하고, 피드백을 받는다.
- codex에게 '점수'를 알려달라하고 95점 이상이 될때까지 수정→검증→수정→검증 작업을 계속 반복한다.
- 받은 피드백에 대해 '무조건적인 수용을 지양'하고, 정말로 수용해야하는지 꼼꼼하게 판단한 후 수용&수정을 진행한다.
- 거절해야할 피드백 항목이 있다면, 다음 '검증' 작업에서는 해당 내용을 프롬프트에 포함시켜서 어떠한 근거로 수용하지 않았는지를 전달한다.
