# Plan

## Authentication (인증)

### User Authentication (회원 인증)

인증 헤더: `X-Loopers-LoginId`, `X-Loopers-LoginPw`

- [x] 인증이 필요한 API는 인증 헤더가 없으면 `401 Unauthorized`를 반환한다
- [x] 인증 헤더의 로그인 ID가 존재하지 않으면 `401 Unauthorized`를 반환한다
- [x] 인증 헤더의 비밀번호가 일치하지 않으면 `401 Unauthorized`를 반환한다
- [x] 인증된 사용자 정보를 컨트롤러에서 사용할 수 있다

---

### Admin Authentication (어드민 인증)

인증 헤더: `X-Loopers-Ldap`

- [x] `X-Loopers-Ldap` 헤더가 없거나 값이 `loopers.admin`과 일치하지 않으면 `401 Unauthorized`를 반환한다
- [x] `/api-admin/v1/**` 경로에 어드민 인증을 적용한다

---

## User (회원)

### 회원가입

입력 정보: 로그인 ID, 비밀번호, 이름, 생년월일, 이메일

- [x] 로그인 ID는 영문과 숫자만 허용한다
- [x] 이메일은 `xx@yy.zz` 형식이어야 한다
- [x] 생년월일은 `yyyy-MM-dd` 형식이어야 한다
- [x] 이름은 빈 값일 수 없다
- [x] 비밀번호는 8~16자의 영문 대소문자, 숫자, 특수문자만 허용한다
- [x] 비밀번호에 생년월일을 포함할 수 없다
- [x] 비밀번호는 암호화하여 저장한다
- [x] 이미 가입된 로그인 ID로는 가입할 수 없다

---

### 내 정보 조회

반환 정보: 로그인 ID, 이름, 생년월일, 이메일

- [x] 이름의 마지막 글자는 `*`로 마스킹한다
- [x] 존재하지 않는 로그인 ID로 조회하면 `404 Not Found`를 반환한다

---

### 비밀번호 수정

입력 정보: 기존 비밀번호, 새 비밀번호

- [x] 기존 비밀번호가 일치해야 수정할 수 있다
- [x] 새 비밀번호는 비밀번호 규칙을 따라야 한다
- [x] 현재 비밀번호와 동일한 비밀번호로는 수정할 수 없다

---

## Order (주문)

### [대고객] 주문 요청

`POST /api/v1/orders` · 인증 필요 · 입력: 상품 ID와 수량 목록

- [ ] 상품 ID와 수량 목록을 입력받아 주문을 생성한다
- [ ] 주문 항목이 1건이면 상품명, 2건 이상이면 "첫 상품명 외 N건"으로 주문 이름을 생성한다
- [ ] 주문 항목은 1개 이상이어야 한다
- [ ] 각 주문 항목의 수량은 1 이상이어야 한다
- [ ] 같은 상품이 중복 포함되면 요청에 실패한다
- [ ] 존재하지 않거나 삭제된 상품이 포함되면 주문에 실패한다
- [ ] 매진(재고 0)인 상품이 포함되면 실패한다
- [ ] 재고가 요청 수량보다 적은 상품이 포함되면 실패한다
- [ ] 여러 상품 중 하나라도 재고가 부족하면 주문 전체가 실패한다
- [ ] 주문 시점의 상품 정보(이름, 가격, 썸네일)를 주문 항목에 스냅샷으로 저장한다
- [ ] 주문 항목별 소계(가격 × 수량)와 주문 총액을 계산한다
- [ ] 주문 생성 시 상태는 CREATED로 설정한다
- [ ] 재고 차감과 주문 생성은 단일 트랜잭션으로 처리하며, 중간 실패 시 전체 롤백된다

---

- [ ] 주문일 기준으로 시작/종료 시간으로 필터링할 수 있다
