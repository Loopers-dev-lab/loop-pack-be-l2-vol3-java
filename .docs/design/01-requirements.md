# 01. 요구사항 명세

## 1. 목적 및 범위

감성 이커머스 서비스의 핵심 도메인에 대한 기능 요구사항을 정의한다.

### 설계 범위

- 브랜드, 상품, 좋아요, 주문

### 범위 고정

- 유저 도메인은 1주차에 완성되었으며, 본 설계 범위에서 제외한다.
- 사용자 기능과 어드민 기능을 구분하여 정의한다.
- 사용자 식별은 헤더 기반으로 처리하며, 별도 인증/인가는 구현하지 않는다.

---

## 2. 유저 시나리오

### 2.1 브랜드

**사용자**

1. 사용자는 특정 브랜드의 정보를 조회할 수 있다.

**어드민**

1. 어드민은 등록된 브랜드 목록을 페이지 단위로 조회할 수 있다.
2. 어드민은 특정 브랜드의 상세 정보를 조회할 수 있다.
3. 어드민은 새로운 브랜드를 등록할 수 있다.
4. 어드민은 브랜드 정보를 수정할 수 있다.
5. 어드민은 브랜드를 삭제할 수 있다.

### 2.2 상품

**사용자**

1. 사용자는 상품 목록을 조회할 수 있다.
2. 사용자는 특정 브랜드의 상품만 필터링하여 조회할 수 있다.
3. 사용자는 정렬 기준을 선택하여 상품 목록을 조회할 수 있다. (최신순, 가격 낮은순, 좋아요 많은순)
4. 사용자는 상품 목록을 페이지 단위로 조회할 수 있다.
5. 사용자는 특정 상품의 상세 정보를 조회할 수 있다.

**어드민**

1. 어드민은 등록된 상품 목록을 페이지 단위로 조회할 수 있다.
2. 어드민은 브랜드별로 상품을 필터링하여 조회할 수 있다.
3. 어드민은 특정 상품의 상세 정보를 조회할 수 있다.
4. 어드민은 새로운 상품을 등록할 수 있다.
5. 어드민은 상품 정보를 수정할 수 있다.
6. 어드민은 상품을 삭제할 수 있다.

### 2.3 좋아요

1. 사용자는 마음에 드는 상품에 좋아요를 누를 수 있다.
2. 사용자는 좋아요를 취소할 수 있다.
3. 사용자는 자신이 좋아요한 상품 목록을 확인할 수 있다.

### 2.4 주문

**사용자**

1. 사용자는 여러 상품을 한 번에 주문할 수 있다.
2. 사용자는 자신의 주문 목록을 기간별로 조회할 수 있다.
3. 사용자는 특정 주문의 상세 내역을 조회할 수 있다.

**어드민**

1. 어드민은 전체 주문 목록을 페이지 단위로 조회할 수 있다.
2. 어드민은 특정 주문의 상세 내역을 조회할 수 있다.

## 3. 비즈니스 규칙

### 3.1 브랜드

- 브랜드 삭제 시, 해당 브랜드에 속한 모든 상품도 함께 삭제된다.
- 삭제된 브랜드는 사용자에게 노출되지 않는다.

### 3.2 상품

- 상품은 반드시 이미 등록된 브랜드에 속해야 한다.
- 상품이 한 번 등록되면, 소속 브랜드는 변경할 수 없다.
- 상품은 옵션(색상, 사이즈 등) 없이 단일 품목으로 관리한다. 재고와 가격은 상품 단위로 관리한다.
- 고객에게 노출되는 상품 정보와 어드민에게 제공되는 상품 정보는 다를 수 있다.
- 삭제된 상품은 사용자에게 노출되지 않는다.
- 상품 삭제 시, 해당 상품에 대한 좋아요도 함께 제거된다.
- 삭제된 상품이 포함된 과거 주문 내역은 스냅샷을 기반으로 정상 조회된다.

### 3.3 좋아요

- 같은 상품에 중복으로 좋아요할 수 없다.
- 좋아요 및 취소는 본인만 할 수 있다.
- 좋아요 취소 시 이력을 보존하지 않고 완전히 제거한다.

### 3.4 주문

- 주문 시 각 상품의 재고를 확인하고 차감한다.
- 주문 항목 중 하나라도 재고가 부족하면 주문 전체를 거부하고, 부족한 상품 정보를 사용자에게 알린다.
- 주문 시 상품 정보(상품명, 가격)를 스냅샷으로 저장한다. 이후 원본 상품이 변경되어도 주문 내역에는 영향이 없다.
- 주문은 생성 시 즉시 ORDERED 상태가 된다. 상태 전이는 추후 결제 연동 시 확장한다.

## 4. 예외 및 정책

### 4.1 브랜드/상품

- 존재하지 않는 브랜드 또는 상품을 조회할 경우 오류로 처리한다.
- 삭제된 브랜드에 상품을 등록할 수 없다.

### 4.2 좋아요

- 이미 좋아요한 상품에 다시 좋아요를 누를 경우 오류로 처리한다.
- 좋아요하지 않은 상품에 좋아요 취소를 요청할 경우 아무 동작 없이 성공으로 처리한다. (멱등)
- 삭제된 상품에 대한 좋아요는 목록에서 제외한다.

### 4.3 주문

- 존재하지 않는 상품을 주문할 경우 오류로 처리한다.
- 삭제된 상품을 주문할 경우 오류로 처리한다.
- 주문 항목이 비어있는 경우 오류로 처리한다.
- 같은 상품을 중복으로 주문 항목에 포함할 경우 오류로 처리한다.
- 주문 수량은 1개 이상이어야 한다.

## 5. 범위에서 제외하는 것들

| 항목 | 사유 |
|------|------|
| 유저 | 1주차에 완성됨 |
| 결제 | 결제팀 분리 예정. 현재는 주문 완료 시 즉시 성공 처리 |
| 쿠폰 | 쿠폰팀 분리 예정. 현재는 할인 로직 미적용 |
| 인증/인가 | 헤더 기반 사용자 식별만 사용 |
| 동시성/멱등성 | 추후 고도화 단계에서 처리 |
| 주문 취소/부분 취소 | 결제 연동 시 함께 설계 예정 |
| 상품 옵션 (색상/사이즈 등) | 현재 단일 품목으로 관리. 추후 옵션별 재고/가격 관리 필요 시 확장 |
