## 개요

이 문서는 감성 이커머스 플랫폼의 기능 및 비기능 요구사항을 정의한다.
인증 체계, 브랜드, 상품, 좋아요, 주문 도메인을 다루며, 각 기능의 유저 스토리와 상세 요구사항을 포함한다.

이번 과제에서는 브랜드/상품/좋아요/주문의 도메인 설계에 집중한다.
동시성 제어, 쿠폰, 결제는 고려하지 않는다.

## Authentication (대고객 인증)

대고객 API(`/api/v1/**`) 중 인증이 필요한 엔드포인트에 적용되는 인증 체계이다.
로그인 ID와 비밀번호로 사용자를 식별하며, 인증된 사용자 정보를 컨트롤러에 주입한다.

인증 헤더: `X-Loopers-LoginId`, `X-Loopers-LoginPw`

#### 기능적 요구사항

- 인증이 필요한 API는 인증 헤더가 없으면 인증에 실패한다.
- 로그인 ID가 존재하지 않으면 인증에 실패한다.
- 비밀번호가 일치하지 않으면 인증에 실패한다.

#### 비기능적 요구사항

- 적용 범위: `/api/v1/**` 중 인증이 필요한 API.

## Admin Authentication (어드민 인증)

어드민 API(`/api-admin/v1/**`)에 접근하기 위한 인증 체계이다.
대고객 인증과는 별개의 독립된 인증 메커니즘이다.

인증 헤더: `X-Loopers-Ldap`

#### 기능적 요구사항

- `X-Loopers-Ldap` 헤더의 값이 `loopers.admin`과 일치하는지 확인한다.
- 헤더가 없거나 값이 일치하지 않으면 인증에 실패한다.

#### 비기능적 요구사항

- 적용 범위: `/api-admin/v1/**` 중 인증이 필요한 API.

## Brand (브랜드)

### [어드민] 브랜드 등록

#### 유저 스토리

관리자는 상품을 등록하기 전에 해당 상품이 속할 브랜드를 먼저 등록해야 한다.
브랜드 이름은 시스템 내에서 유일해야 하며, 같은 이름으로 중복 등록할 수 없다.

#### 기능적 요구사항

- 브랜드 이름(필수), 로고 URL(필수), 설명을 입력받아 브랜드를 생성한다.
- 브랜드 이름은 2자 이상 50자 이하여야 한다.
- 활성 상태의 브랜드 중 동일한 이름이 있으면 등록에 실패한다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 삭제된 브랜드와 동일한 이름으로 재등록이 가능하다.
- 설명은 선택 값이다.

### [어드민] 브랜드 목록 조회

#### 유저 스토리

관리자는 등록된 브랜드 목록을 확인하여 브랜드를 관리해야 한다.
브랜드가 많아질 경우를 대비하여 페이지 단위로 나눠서 조회하며, 삭제된 브랜드도 포함하여 전체 현황을 파악할 수 있어야 한다.

#### 기능적 요구사항

- 등록된 브랜드를 페이지 단위로 조회한다.
- 삭제된 브랜드도 조회 대상에 포함한다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 기본 정렬은 생성일 내림차순이다.

### [어드민] 브랜드 상세 조회

#### 유저 스토리

관리자는 특정 브랜드의 전체 정보(이름, 로고, 설명 포함)를 확인하여 브랜드 수정/삭제 등 후속 작업 전에 현재 상태를 파악해야 한다.
삭제된 브랜드도 조회하여 삭제 여부와 과거 상태를 파악할 수 있어야 한다.

#### 기능적 요구사항

- 단일 브랜드의 전체 정보를 조회한다. (삭제된 브랜드 포함)
- 존재하지 않는 브랜드는 조회할 수 없다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.

### [어드민] 브랜드 정보 수정

#### 유저 스토리

관리자는 브랜드 리브랜딩, 로고 변경, 설명 보완 등의 이유로 등록된 브랜드의 정보를 수정해야 한다.
수정 시에도 브랜드 이름의 유일성은 유지되어야 한다.

#### 기능적 요구사항

- 브랜드 ID, 수정할 이름(필수), 로고 URL(필수), 설명을 입력받아 브랜드 정보를 수정한다.
- 브랜드 이름은 2자 이상 50자 이하여야 한다.
- 자기 자신을 제외한 활성 상태의 브랜드 중 동일한 이름이 있으면 수정에 실패한다.
- 존재하지 않는 브랜드는 수정할 수 없다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 설명은 선택 값이다.

### [어드민] 브랜드 삭제

#### 유저 스토리

관리자는 더 이상 운영하지 않는 브랜드를 삭제하여 시스템에서 제거해야 한다.
브랜드를 삭제하면 해당 브랜드에 소속된 상품과 그 상품의 좋아요도 함께 삭제되어야 한다.

#### 기능적 요구사항

- 브랜드를 삭제한다.
- 존재하지 않는 브랜드는 삭제할 수 없다.
- 이미 삭제된 브랜드는 삭제할 수 없다.
- 해당 브랜드에 소속된 상품의 좋아요를 모두 삭제한다.
- 해당 브랜드에 소속된 상품을 모두 삭제한다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 단일 트랜잭션으로 처리하며, 중간 실패 시 전체 롤백된다.

### [대고객] 브랜드 상세 조회

#### 유저 스토리

고객은 상품 탐색 전 브랜드의 상세 정보(이름, 로고, 설명)를 확인할 수 있어야 한다.
인증 없이 접근 가능하다.

#### 기능적 요구사항

- 단일 브랜드 정보를 조회한다.
- 존재하지 않거나 삭제된 브랜드는 조회할 수 없다.

#### 비기능적 요구사항

- 인증이 필요하지 않다.

## Product (상품)

### [어드민] 상품 등록

#### 유저 스토리

관리자는 브랜드에 속하는 상품을 등록하여 고객이 구매할 수 있는 상품 카탈로그를 구축해야 한다.
반드시 존재하는 브랜드에 소속되어야 한다.

#### 기능적 요구사항

- brandId, 상품명, 가격, 재고, 썸네일 이미지 URL, 상세 설명을 입력받아 상품을 생성한다.
- 이름, 가격, 재고, 썸네일 이미지 URL은 필수값이다.
- 상품명은 2자 이상 100자 이하여야 한다.
- 가격은 0 이상이어야 한다.
- 재고는 1 이상이어야 한다.
- brandId에 해당하는 브랜드가 존재하지 않거나 삭제된 상태이면 요청에 실패한다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 상세 설명은 선택 값이다.

### [어드민] 상품 목록 조회

#### 유저 스토리

어드민은 등록된 상품 목록을 확인하여 상품을 관리해야 한다.
상품이 많아질 경우를 대비하여 페이지 단위로 나눠서 조회하며, 특정 브랜드의 상품만 필터링하여 볼 수 있다.
삭제된 상품도 포함하여 전체 현황을 파악할 수 있어야 한다.

#### 기능적 요구사항

- 등록된 상품을 페이지 단위로 조회한다. (삭제된 상품 포함)
- brandId가 전달된 경우 해당 브랜드의 상품만 필터링한다.
- brandId가 전달되지 않으면 전체 상품을 조회한다.
- 존재하지 않는 브랜드로는 필터링할 수 없다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 기본 정렬은 생성일 내림차순이다.
- 기본 페이지 크기는 20건이다.
- 삭제된 브랜드로도 필터링할 수 있다.

### [어드민] 상품 상세 조회

#### 유저 스토리

관리자는 상품 수정/삭제 등 후속 작업 전에 상품의 전체 정보를 확인해야 한다.
삭제된 상품도 조회하여 삭제 여부와 과거 상태를 파악할 수 있어야 한다.

#### 기능적 요구사항

- 단일 상품의 정보를 조회한다. (삭제된 상품 포함)
- 존재하지 않는 상품은 조회할 수 없다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.

### [어드민] 상품 정보 수정

#### 유저 스토리

관리자는 상품명 변경, 가격 조정, 재고 수정, 이미지 교체 등의 이유로 등록된 상품의 정보를 수정해야 한다.

#### 기능적 요구사항

- 상품 ID, 수정할 이름(필수), 가격(필수), 재고(필수), 썸네일 이미지 URL(필수), 상세 설명을 입력받아 상품 정보를 수정한다.
- 상품명은 2자 이상 100자 이하여야 한다.
- 가격은 0 이상이어야 한다.
- 재고는 1 이상이어야 한다.
- 존재하지 않는 상품은 수정할 수 없다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 소속 브랜드는 수정할 수 없다.
- 상세 설명은 선택 값이다.

### [어드민] 상품 삭제

#### 유저 스토리

관리자는 더 이상 판매하지 않는 상품을 삭제하여 고객에게 노출되지 않도록 해야 한다.
상품을 삭제하면 해당 상품에 등록된 좋아요도 함께 삭제되어야 한다.

#### 기능적 요구사항

- 상품을 삭제한다.
- 존재하지 않는 상품은 삭제할 수 없다.
- 이미 삭제된 상품은 삭제할 수 없다.
- 해당 상품에 등록된 좋아요를 모두 삭제한다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 단일 트랜잭션으로 처리하며, 중간 실패 시 전체 롤백된다.

### [대고객] 상품 목록 조회

#### 유저 스토리

고객은 상품 카탈로그를 탐색하여 원하는 상품을 찾을 수 있어야 한다.
브랜드별 필터링, 다양한 정렬 옵션(최신순, 가격순, 좋아요순)을 지원하여 편리한 상품 탐색 경험을 제공한다.
인증 없이 접근 가능하다.

#### 기능적 요구사항

- 활성 상태의 상품을 페이지 단위로 조회한다.
- brandId가 전달된 경우 해당 브랜드의 상품만 필터링한다.
- brandId를 생략하면 전체 활성 브랜드의 상품을 반환한다.
- 존재하지 않거나 삭제된 브랜드로는 필터링할 수 없다.
- 정렬 옵션을 지원한다. (등록일 내림차순, 가격 오름차순, 좋아요 수 내림차순)
- 유효하지 않은 정렬 옵션을 전달하면 요청에 실패한다.

#### 비기능적 요구사항

- 인증이 필요하지 않다.
- 삭제된 상품과 삭제된 브랜드의 상품은 조회 대상에서 제외한다.
- 기본 정렬은 등록일 내림차순이다.
- 기본 페이지 크기는 20건, 최대 100건이다.

### [대고객] 상품 상세 조회

#### 유저 스토리

고객은 상품 상세 페이지에서 구매 의사결정에 필요한 정보(이름, 가격, 재고, 설명, 좋아요 수 등)를 확인할 수 있어야 한다.
인증 없이 접근 가능하다.

#### 기능적 요구사항

- 단일 상품의 상세 정보를 조회한다.
- 존재하지 않거나 삭제된 상품은 조회할 수 없다.

#### 비기능적 요구사항

- 인증이 필요하지 않다.

## Like (좋아요)

### [대고객] 상품 좋아요 등록

#### 유저 스토리

고객은 마음에 드는 상품에 좋아요를 등록하여 관심을 표시할 수 있어야 한다.
좋아요 등록은 멱등하게 동작하여, 이미 좋아요를 누른 상품에 다시 요청하더라도 에러 없이 동일한 결과를 반환한다.
인증된 사용자만 좋아요를 등록할 수 있다.

#### 기능적 요구사항

- 좋아요를 등록한다.
- 좋아요 등록 시 해당 상품의 좋아요 수가 1 증가한다.
- 이미 좋아요가 존재하면 아무 동작 없이 성공한다.
- 존재하지 않거나 삭제된 상품에는 좋아요를 등록할 수 없다.

#### 비기능적 요구사항

- 인증이 필요하다.
- 멱등성을 보장한다. 이미 좋아요가 존재하면 에러 없이 성공한다.
- 한 사용자는 동일한 상품에 하나의 좋아요만 등록할 수 있다.

### [대고객] 상품 좋아요 취소

#### 유저 스토리

고객은 이전에 등록한 좋아요를 취소하여 관심 표시를 철회할 수 있어야 한다.
좋아요 취소는 멱등하게 동작하여, 이미 취소된 상태에서 다시 요청하더라도 에러 없이 동일한 결과를 반환한다.
인증된 사용자만 좋아요를 취소할 수 있다.

#### 기능적 요구사항

- 좋아요를 취소한다.
- 좋아요 취소 시 해당 상품의 좋아요 수가 1 감소한다.
- 좋아요가 존재하지 않으면 아무 동작 없이 성공한다.
- 존재하지 않거나 삭제된 상품의 좋아요는 취소할 수 없다.

#### 비기능적 요구사항

- 인증이 필요하다.
- 멱등성을 보장한다. 이미 취소된 상태에서 다시 취소해도 에러 없이 성공한다.

### [대고객] 내가 좋아요한 상품 목록 조회

#### 유저 스토리

고객은 자신이 좋아요를 등록한 상품 목록을 조회하여 관심 상품을 한눈에 확인하고 구매 의사결정에 활용할 수 있어야 한다.
인증된 사용자만 자신의 좋아요 목록을 조회할 수 있다.

#### 기능적 요구사항

- 인증된 유저가 좋아요한 상품 목록을 페이지 단위로 조회한다.
- 좋아요가 없으면 빈 페이지를 반환한다.

#### 비기능적 요구사항

- 인증이 필요하다.
- 삭제된 상품과 삭제된 브랜드에 소속된 상품은 조회 대상에서 제외한다.

## Order (주문)

### [어드민] 주문 목록 조회

#### 유저 스토리

관리자는 플랫폼 전체의 주문 현황을 파악하기 위해 모든 주문을 조회할 수 있어야 한다.
삭제된 주문도 포함하여 전체 현황을 파악할 수 있어야 하며, 주문이 많아질 경우를 대비하여 페이지 단위로 나눠서 조회한다.
각 주문은 주문 이름(첫 상품명 외 N건)으로 요약하여 목록에서 빠르게 내용을 파악할 수 있도록 한다.

#### 기능적 요구사항

- 전체 주문을 페이지 단위로 조회한다.
- 모든 주문 상태의 주문을 조회 대상에 포함한다.
- 주문이 없으면 빈 페이지를 반환한다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 기본 정렬은 생성일 내림차순이다.
- 기본 페이지 크기는 20건, 최대 100건이다.

### [어드민] 주문 상세 조회

#### 유저 스토리

관리자는 CS 대응, 결제 확인, 주문 현황 파악 등을 위해 특정 주문의 상세 정보를 조회할 수 있어야 한다.
대고객 API와 달리 소유권 제한 없이 모든 사용자의 주문을 조회할 수 있으며, 주문자 정보(userId, 마스킹된 이름)를 함께 확인할 수 있다.

#### 기능적 요구사항

- 주문 상세 정보를 조회한다.
- 존재하지 않는 주문은 조회할 수 없다.

#### 비기능적 요구사항

- 어드민 인증이 필요하다.
- 소유권 검증 없이 모든 주문을 조회할 수 있다.
- 주문자 이름은 마스킹하여 반환한다.

### [대고객] 주문 요청

#### 유저 스토리

고객은 원하는 상품을 여러 개 선택하여 한 번에 주문할 수 있어야 한다.
주문 시점에 재고가 차감되며, 재고가 부족하거나 매진된 상품이 포함되어 있으면 주문 전체가 실패한다.
인증된 사용자만 주문할 수 있다.

#### 기능적 요구사항

- 상품 ID와 수량 목록을 입력받아 주문을 생성한다.
- 주문 이름은 주문 항목의 첫 번째 상품명을 기준으로 생성한다.
  - 주문 항목이 1건이면: 상품명 (예: "블랙 티셔츠")
  - 주문 항목이 2건 이상이면: "첫 상품명 외 N건" (예: "블랙 티셔츠 외 2건", N = 전체 항목 수 - 1)
- 주문 항목은 1개 이상이어야 한다.
- 각 주문 항목의 수량은 1 이상이어야 한다.
- 같은 상품이 중복 포함되면 요청에 실패한다.
- 존재하지 않거나 삭제된 상품이 포함되면 주문에 실패한다.
- 매진(재고가 0개)인 상품이 포함되면 실패한다.
- 재고가 요청 수량보다 적은 상품이 포함되면 실패한다.
- 여러 상품 중 하나라도 재고가 부족하면 주문 전체가 실패한다.
- 주문 시점의 상품 정보(이름, 가격, 썸네일 이미지 등)를 주문 항목에 스냅샷으로 저장한다.
- 주문 항목별 소계(가격 × 수량)와 주문 총액을 계산한다.
- 주문 생성 시 상태는 CREATED로 설정한다.

#### 비기능적 요구사항

- 인증이 필요하다.
- 재고 차감과 주문 생성은 단일 트랜잭션으로 처리하며, 중간 실패 시 전체 롤백된다.
- 상품 삭제 후에도 주문 기록은 유지한다.

### [대고객] 주문 목록 조회

#### 유저 스토리

고객은 자신의 주문 이력을 조회하여 구매 내역을 확인할 수 있어야 한다.
특정 기간의 주문만 필터링하여 볼 수 있으며, 주문이 많아질 경우를 대비하여 페이지 단위로 조회한다.
인증된 사용자만 본인의 주문을 조회할 수 있다.

#### 기능적 요구사항

- 인증된 사용자 본인의 주문 목록을 페이지 단위로 조회한다.
- 주문일 기준으로 시작 시간과 종료 시간으로 필터링할 수 있다.
- 시작 시간과 종료 시간을 생략하면 최근 3개월을 기본값으로 적용한다.
- 주문이 없으면 빈 페이지를 반환한다.

#### 비기능적 요구사항

- 인증이 필요하다.
- 기본 정렬은 주문일 내림차순이다.
- 기본 페이지 크기는 20건, 최대 100건이다.

### [대고객] 주문 상세 조회

#### 유저 스토리

고객은 특정 주문의 상세 정보를 조회하여 주문한 상품 내역, 수량, 금액 등을 확인할 수 있어야 한다.
본인의 주문만 조회할 수 있으며, 다른 사용자의 주문에는 접근할 수 없다.
인증된 사용자만 주문 상세를 조회할 수 있다.

#### 기능적 요구사항

- 주문 상세 정보를 조회한다.
- 존재하지 않는 주문은 조회할 수 없다.
- 다른 사용자의 주문을 조회하면 실패한다.

#### 비기능적 요구사항

- 인증이 필요하다.
