## Thundering Herd

### 개념

특정 이벤트를 기다리던 다수가 동시에 깨어나서 한꺼번에 몰리는 현상.
단순 트래픽 폭증과 다르게, **시스템이 스스로 만들어낸 폭증**이다.

이 프로젝트 맥락에서는 스케줄러가 토큰을 발급하는 순간이 트리거가 된다.

```
스케줄러가 1초마다 175명에게 토큰 발급
→ 175명이 동시에 주문 API 호출
→ 순간적으로 175개의 요청이 동시에 DB 히트
```

---

### 완화 방법: ms 단위 배치 발급

초당 처리량을 한 번에 발급하지 않고, ms 단위로 쪼개서 발급한다.

```
1초에 175명 한 번에 발급 → 순간 스파이크
100ms마다 18명씩 발급   → 고른 흐름
```

같은 처리량이지만 덜 몰리게 하는 것이 핵심이다.

서버 보호가 목적이므로 서버가 직접 제어하는 것이 원칙에 맞다.
Jitter처럼 클라이언트에 의존하는 방식은 클라이언트가 무시해도 막을 방법이 없다.

---

### Thundering Herd vs 단순 트래픽 폭증

| | 단순 트래픽 폭증 | Thundering Herd |
|---|---|---|
| 원인 | 외부에서 유입 | 시스템 내부 이벤트가 트리거 |
| 예시 | 블랙프라이데이 오픈 | 토큰 일괄 발급, 캐시 만료 |
| 대응 | 대기열, Rate Limiting | 배치 쪼개기, 순차 발급 |
